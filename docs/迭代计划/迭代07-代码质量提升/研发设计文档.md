## 1. 设计目标与原则

### 1.1 目标

把质量治理从"**靠人扫**"改成"**靠门禁挡 + 靠台账推**"：

1. 门禁覆盖全部源码（含 15 个子仓），有明确的**例外清单**；
2. 违规量**单调不增**（棘轮），杜绝"清理一批、新增两批"；
3. 债务**单一台账**可查、可分配、可验收；
4. 修复**分批可回滚**，每批测试全绿。

### 1.2 设计原则

1. **先堵漏再清存量**：没有门禁的清理等于白干（实测一个月 +458 违规即证据）。
2. **棘轮优于阈值**：不设"必须低于 N"的绝对门槛（会一次达标后继续劣化），而是"**不得超过已达成的最好水平**"。
3. **例外显式化**：生成代码（CTP structs）、测试桩（S106）等必须有**书面例外清单 + 理由 + 复核日期**，不允许静默 ignore。
4. **按仓分批**：每个子仓独立提交、独立验证、独立回滚；父仓只 bump 指针。
5. **可复现**：所有指标都能用一条命令重算，避免"文档说 80、CI 管 40"式的失真。

                                  │
                                  ▼

### 2.1 分层职责

| 层 | 位置 | 职责 |
|----|------|------|
| 本地钩子 | `.pre-commit-config.yaml` | 提交即修（ruff --fix / format）；拦截私钥与调试语句 |
| 本地命令 | `Makefile` | 一键跑 lint/type-check/security-scan；**扩容到子仓** |
| CI 门禁 | `.github/workflows/tests.yml` | PR 必须通过；**新增棘轮比对** |
| 基线快照 | `docs/acceptance/<date>-quality-baseline.json` | 机器可读的违规量与覆盖率快照（棘轮依据） |
| 棘轮脚本 | `scripts/ci/check_quality_ratchet.py`（新增） | 比对当前扫描 vs 快照，只许下降 |
| 债务台账 | `docs/tech-debt.md`（新增） | 人可读的登记册；与快照互补 |

## 3. 核心机制设计

### 3.1 门禁范围扩容（D1 的落地方式）

现状：`Makefile` 的 `lint: ruff check bt_api_py/ tests/`、`type-check: mypy bt_api_py/`；
CI Quality Gates 同样只扫 `bt_api_py`、`tests`。**`bt_api/*/src`（≈25 万行）完全无门禁**。

设计：

```make
# 统一的范围变量，避免各地手抄路径
PKG_MAIN   := bt_api_py
PKG_SUB    := $(wildcard bt_api/bt_api_*/src)
QUALITY_SCOPE := $(PKG_MAIN) tests $(PKG_SUB)

lint:            ruff check $(QUALITY_SCOPE)
type-check:      mypy $(QUALITY_SCOPE) --ignore-missing-imports
security-scan:   bandit -r $(QUALITY_SCOPE) -c pyproject.toml
```

CI 侧按**分层 job + 矩阵**执行，避免单 job 超时（现状 Quality Gates `timeout-minutes: 15`）：

| job | 范围 | 超时 | 说明 |
|-----|------|------|------|
| `quality-core` | `bt_api_py` + `tests` | 15 min | 保持现有严格度（当前 clean） |
| `quality-submodules` | 矩阵：每个 `bt_api/bt_api_*` 一个分片 | 10 min/分片 | 新增；失败只定位到具体子仓 |
| `quality-ratchet` | 全量扫描 + 快照比对 | 10 min | 新增；只判断"是否上升" |

> 取舍：矩阵 jobs 会增加 CI 分钟数，但换来"子仓失败可定位、可并行、可单独豁免"。
> 若 CI 预算紧张，可退化为单 job `--statistics` + ratchet，但**不可不覆盖**。

### 3.2 棘轮（Ratchet）机制

**基线快照格式**（`docs/acceptance/<YYYY-MM-DD>-quality-ratchet.json`）：

```json
{
  "schema_version": 1,
  "generated_at": "2026-09-19T00:00:00+08:00",
  "scope": ["bt_api_py", "tests", "bt_api/*/src"],
  "ruff_version": "ruff 0.16.2",
  "ruff": { "total": 1301, "by_rule": { "W291": 712, "F401": 164, "I001": 154, "F821": 135, "S106": 45, "E701": 36, "F541": 21 } },
  "ruff_exceptions": { "paths": ["bt_api/bt_api_ctp/src/bt_api_ctp/ctp/ctp_structs_*.py"], "reason": "生成代码" },
  "mypy": { "total": 74, "scope": ["bt_api_py"] },
  "coverage": { "bt_api_py": 40.0, "enforced_min": 40 }
}
```

**判定规则**（`scripts/ci/check_quality_ratchet.py`）：

1. 逐规则比较：`current[rule] > baseline[rule]` → **fail**（并打印新增位置的前 N 条）。
2. 规则新增（baseline 无、current 有）→ fail（除非在 `allow_new_rules` 白名单）。
3. 规则清零 → **pass，并提示更新快照**（快照只在下降时更新，单调不增）。
4. 例外路径在扫描时排除，但**例外清单本身纳入审查**（新增例外需在本计划或 ADR 中说明理由）。

> 与"绝对阈值门禁"的区别：绝对阈值只保证"不比目标差"，棘轮保证"不比历史最好差"，
> 适合长期劣化型债务（本项目实测一个月 +458，正属此类）。

### 3.3 债务台账（单一入口）

`docs/tech-debt.md` 结构（可勾选、可分配、可验收）：

| ID | 类别 | 描述 | 证据命令 | 批次 | 状态 | 目标 |
|----|------|------|---------|------|------|------|
| Q-001 | 缺陷 | okx `*_partN` 切分丢 import（89 处 F821） | `ruff check bt_api/bt_api_okx --select F821` | M1 | TODO | 0 |
| Q-002 | 安全 | 测试文件含真实账号 `089763` | `git grep -n 089763` | M1 | TODO | 0 |
| Q-003 | 门禁 | 子仓无 ruff/mypy 门禁 | `make lint` 覆盖范围 | M2 | TODO | 全覆盖 |
| Q-010 | 结构 | `bt_api.py` 8864 行 | `scripts/check_file_sizes.py` | M5 | TODO | ≤2000（方案） |
| Q-020 | 覆盖率 | 主包覆盖率 40% | `pytest --cov=bt_api_py` | M5 | TODO | 55% |
| Q-030 | 配置 | `pyrightconfig.json` 路径失效 | `ls bt_api_base` | M1 | TODO | 修复/删除 |
| Q-031 | 配置 | `AGENTS.md` 引用缺失规则文件 | `ls .joyincode/rules` | M1 | TODO | 修复 |

- **生成方式**：`scripts/ci/render_tech_debt.py`（新增）可从扫描结果生成候选行，人工确认后入库（避免手抄失真）。
- **生命周期**：新增债务（PR 引入且被例外豁免）必须同时新增台账行；关闭时更新状态并附证据。

### 3.4 例外清单（Explicit Waivers）

| 例外 | 范围 | 理由 | 复核 |
|------|------|------|------|
| CTP 结构体/常量映射 | `bt_api_ctp/src/**/ctp_structs_*.py`、`ctp_constants.py`、`ctp_wrap.*` | SWIG/字段映射产物，风格无意义 | 每迭代复核一次 |
| 测试桩硬编码口令 | `S106`（22 处，均在 tests） | 演示凭据，非真实密钥 | 改为占位常量后取消例外 |
| 兼容性别名 | 视扫描结果 | 公开 API 兼容 | 个案登记 |

例外必须在 `pyproject.toml` 的 `per-file-ignores` + 本文件双处可见，with理由，不允许散落。

### 3.5 子仓批量治理与发布

`bt_api/*` 是独立 git 仓库，改动流程：

```
① 在子仓 dev 分支创建 fix/quality-<topic> 分支
② 只做单一主题改动（如"补 import 修 F821"）
③ 子仓测试全绿 + ruff 该仓 clean
④ 提交（Conventional Commits）→ 按需要发版
⑤ 父仓 bump 子模块指针（chore: pin bt_api_x for ...）
```

- 子仓**不强制发版**：是否发版由 owner 决定；父仓指针更新与发版解耦。
- 批量脚本：`scripts/ci/foreach_submodule.sh`（新增，可选）按清单遍历执行 ruff/test，输出汇总表。

### 3.6 结构治理设计（不重写）

对每个超长文件产出**拆分方案卡**（`docs/refactor/<file>.md`），字段固定：

| 字段 | 内容 |
|------|------|
| 现状 | 行数、职责簇、对外入口 |
| 风险 | 该文件被谁依赖、改动回归面 |
| 拆分边界 | 按职责切到哪几个模块（给出模块名与函数归属） |
| 回归测试 | 拆分前后必须全绿的测试清单 |
| 是否本期执行 | 是/否 + 理由（默认"否"，仅方案） |

优先文件：`bt_api.py`(8864) / `_execution_session.py`(8251) / `ctp/client.py`(4002) / `_normalization.py`(2511) / `live_ctp_feed.py`(2025)。

### 3.7 覆盖率门槛同源

- 单一事实来源：`pyproject.toml` 的 `[tool.coverage.report] fail_under = <value>`。
- CI 使用 `--cov-fail-under` 时**不写死**，由 `pyproject` 或缺省读取，或在 CI env 中引用同一常量并加注释交叉引用。
- 每次提升门槛，同步更新 `docs/CODE_QUALITY.md` 与基线快照（消除 40 vs 80 的文档失真）。

## 4. 验证设计

| 项 | 命令 | 判据 |
|----|------|------|
| ruff 全仓 | `ruff check bt_api_py tests $(ls -d bt_api/bt_api_*/src)` | 违规数 ≤ 棘轮基线 |
| ruff 子仓定位 | `ruff check bt_api/bt_api_okx/src --select F821` | 0 |
| 格式 | `ruff format --check <scope>` | clean |
| mypy | `mypy bt_api_py tests --ignore-missing-imports` | 错误数 ≤ 基线 |
| bandit | `bandit -r bt_api_py -c pyproject.toml` | 无 High |
| 覆盖率 | `pytest tests -m "<CI 标记>" --cov=bt_api_py --cov-fail-under=<值>` | ≥ 门槛 |
| 账号泄漏 | `git grep -n 089763` | 0 |
| 棘轮 | `python scripts/ci/check_quality_ratchet.py` | pass |
| 超长文件 | `python scripts/check_file_sizes.py` | 超限数 ≤ 基线（例外面单内） |
| 注解/文档 | `python scripts/analyze_docstrings.py`（或新增 AST 统计脚本） | 公开函数 ≥ 目标 |

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 棘轮过严导致 PR 无法合并 | 高 | 提供**显式例外**通道（台账登记 + ADR），但例外也需记账 |
| 子仓门禁扩容后大量 job 失败、阻塞协作 | 高 | 分两步：先"只扫描不阻塞"（report-only）N 天，再切为阻塞；矩阵分片定位 |
| `ruff --fix` 批量改写引入行为变化 | 中 | 仅用安全修复（不带 `--unsafe-fixes`）；按子仓小批提交 + 测试全绿 |
| 子仓 15 个仓库的协调成本 | 中 | 先做 binance/okx（违规集中），其余按批；用 foreach 脚本汇总 |
| 覆盖率提升靠"补空壳测试" | 中 | 强制 `docs/code-quality-baseline.md` 的反空壳判据；高风险模块优先 |
| 文档与门禁再次失真（40 vs 80） | 中 | 覆盖率门槛同源 + 每次变更同步快照 |
| 计划债台账化沦为形式 | 低 | 台账与 CI 棘轮/批次验收挂钩，纳入验收文档 |
