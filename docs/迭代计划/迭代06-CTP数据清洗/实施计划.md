## 1. 全局约束

1. **不改迭代04 代码**：`collector/`、`collector_ctp/` 只读复用
   （唯一允许：若 sink 原语需要公开化——去掉下划线或加公开别名——
   以最小 diff 提供并在实施记录中说明）。
2. `cleaner/` 包内禁止 import CTP 专属模块（测试断言，对齐迭代04 惯例）；
   CTP 品种规则只放 `cleaner_ctp/`。
3. 所有配置默认相对路径（相对仓库根），沿用迭代04 启动脚本 cd 仓库根的惯例。
4. 远程删除相关代码必须先写测试（含失败路径），再写实现（对齐
   superpowers:test-driven-development 流程要求）。

## 2. 任务清单

### Task 1：配置与 CLI 骨架（M1 前置）

- 内容：`config.py`（cleaner.yaml 加载 + 严格校验：未知字段/未知 backend 拒绝）、
  `cli.py`（`run` / `pull` / `merge` / `kline` / `check-hosts` 子命令骨架、
  `--dry-run`、退出码骨架）、`examples/cleaner.example.yaml`。
- 产出文件：`cleaner/{__init__,__main__,cli,config}.py`、`examples/cleaner.example.yaml`。
- 验证：单测——合法配置解析、非法配置（未知字段/缺 hosts）报错与退出码 1；
  `python -m bt_api_ctp.cleaner --help` 冒烟。

### Task 2：合并核心（M1）

- 内容：`merge.py` 的 `merge_instrument()`——多源同合约文件 +
  权威库现有文件拼接 → 复用 `collector.sink` 的 `_dedup_sort` /
  `_write_atomically` 原子写回；返回 `{added, deduped, total}`；
  schema 漂移防御（按字段名对齐、缺列 null + 告警）。
- 验证：单测——
  - 远程与本地重叠 tick（同键不同 `local_receive_time`）合并后唯一、取最新；
  - 纯新增、空目标文件、三源合并场景；
  - 重跑幂等（第二次 merge 不再增加行数）；
  - 权威库文件被原子替换（无中间态可见）。

### Task 3：传输后端（M2）

- 内容：`pull/backend.py`（`PullBackend` 协议、`RemoteFile`、`FetchResult`）、
  `local_backend.py`（本地复制，测试用）、`rsync_backend.py`
  （subprocess rsync + ssh，排除 `*.lock`/staging）、`sftp_backend.py`
  （先核对依赖树再定 paramiko vs 系统 sftp，见开放问题 1）。
  `check-hosts` 子命令（各机器 `check()` 连通性报告）。
- 验证：单测（local 后端：清单、增量跳过、排除规则）+
  集成测试（`local` 后端模拟两台"远程"源目录，跑通 list→fetch 全流程）；
  rsync/sftp 后端对 `localhost` / 本机 sshd 各做一次冒烟（真实验收放 M5）。

### Task 4：校验与 manifest（M2）

- 内容：`manifest.py`（状态机 + 原子写 JSON）；三级校验
  （清单一致 / 字节数一致 / parquet 可读 + 行数记录）；
  `failed` 态错误信息留痕。
- 验证：单测——
  - 正常流程状态逐步推进并持久化；崩溃重跑从最后状态续推；
  - 篡改场景：staging 少文件 / size 不符 / parquet 损坏 → `failed`，
    报告列出差异文件；
  - manifest 原子写（并发/中断不留半文件）。

### Task 5：远程安全删除（M2）

- 内容：`delete` 阶段——仅对 manifest `merged` 且未 `deleted` 的目录执行；
  白名单校验（`remote_data_root` 前缀 + `YYYYMMDD` 目录名）；
  `delete_remote_after_verify: false` 时只报告不删；`--dry-run` 打印将删路径。
- 验证：单测（**先写**）——
  - 状态不为 `merged` 时绝不调用 backend.delete；
  - 路径逃逸（`..`、绝对路径、非日期名）被白名单拒绝；
  - 配置关闭时不删；dry-run 不产生删除调用（用 fake backend 断言调用次数）。

### Task 6：品种规则表（M3）

- 内容：`cleaner_ctp/symbols.py`（六所期货+期权正则规则表，见设计 3.5）；
  `extract_symbol()`；unknown 清单输出。
- 验证：单测——六所样例全覆盖（SHFE rb2510/rb2510C3200、INE sc2510/sc2510P600、
  DCE m2509/m2509-C-3000、CZCE SR509/SR509C5000、CFFEX IF2509/IO2509-C-4000、
  GFEX si2512/si2512-C-12000 等）；
  **真实清单校准脚本**：对 `ctp_data/2026091{7,8}` 与 `20260921` 的全部
  合约文件名跑识别，要求 100% 识别率（不达标先修规则再继续）。

### Task 7：K 线聚合器（M3）

- 内容：`kline/schema.py`（Bar + parquet schema）、`kline/aggregator.py`
  （`aggregate_1min` / `aggregate_from_1min`，规则见设计 3.4）。
- 验证：单测——
  - OHLC 正确性（手工构造 tick 序列对照）；
  - volume/amount 差分：常规、当日首桶、跨日重置（负差兜底）、钳 0 告警；
  - 无效价过滤（0 / inf 的 last_price 不参与 OHLC）；
  - 夜盘跨零点分桶、小节休息无空桶；
  - 自洽性：`sum(1min.volume) == 5min.volume == 15min.volume`，
    `1min.close 末 == 15min.close`。

### Task 8：K 线写回与回填（M3）

- 内容：`kline/writer.py`（`append_bars` 按 datetime 键合并、新桶覆盖、
  排序、原子替换）；`kline` 子命令（`--day` / `--backfill --since`）；
  路径生成 `kline_root/<exchange>/<symbol>/<instrument>_{period}.parquet`。
- 验证：单测——追加不重复、同桶覆盖、跨日排序、unknown 合约跳过并进报告；
  集成——用 20260918 真实数据合成若干合约，行数/路径/首末桶时间人工核对。

### Task 9：编排与报告（M4）

- 内容：`pipeline.py`（run 一条龙：交易日判断复用迭代04 日历、进程锁、
  磁盘空间预检、staging 用后清理）、`report.py`（`clean-<day>.json`：
  各机器各目录状态、合并/K 线统计、异常清单、各阶段耗时）。
- 验证：集成测试——`local` 后端双源 + 预置权威库，跑完整 `run`，
  断言：合并结果、远程（fake）删除调用、报告结构、退出码；
  重叠运行被进程锁拒绝。

### Task 10：部署与调度（M4）

- 内容：`deploy/cleaner/`（crontab.example：`0 16 * * 1-5`、launchd plist、
  README 含夜盘归属与 16:00 时序论证）；`ctp_data/cleaner.example.yaml`
  本机样例；文档收口（README 数据消费示例：读 tick / 读 K 线）。
- 验证：`--check-calendar` 等价冒烟（非交易日 exit 3）；crontab/launchd
  在本机装载并手动触发一次 `--dry-run` 成功。

### Task 11：真实验收与回填（M5）

- 内容：对本地已有三个交易日跑 `kline --backfill` 全量回填；
  真机拉取演练（Linux rsync 一台 + Windows SFTP 一台，各预置小分片数据）；
  删除演练（`--dry-run` → 实删一次 → 核对远程清理与本地完整性）；
  更新 `验收文档.md` 实现进度与证据章节。
- 验证：见 `验收文档.md` AC 清单逐项执行记录。

## 5. 已知限制（实施时保持透明）

- SFTP 后端性能上限未定（Windows 侧），首日全量迁移若过慢，可退化为
  `local` 后端 + 移动介质一次性导入，日常增量走 SFTP。
- 品种规则表依赖交易所现行命名规范，新规则（如 CZCE 品种扩位、GFEX 新品种）
  需随真实清单校准脚本每月复核一次。
- 16:00 调度依赖本地电脑开机；长期关机场景的数据集中延迟由补拉机制兜底，
  但 K 线回填需要手动触发一次。
