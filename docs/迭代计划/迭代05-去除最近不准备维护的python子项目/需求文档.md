## 1. 背景与目标

### 1.1 背景

`bt_api_py` 通过 `.gitmodules` 挂载 60 个交易所插件 submodule（`bt_api/bt_api_*`，另有基础包 `bt_api_base`）。这些子项目各自独立发版、独立测试，主仓库需要长期承担：

- submodule 的 pin 维护与同步（`scripts/bump_all_submodules.py`、`scripts/git_push_all.*`）；
- 每日全量 submodule 诊断 CI（`.github/workflows/submodule-tests.yml` 的 `submodule-diagnostic`）；
- 仓库体积、clone 耗时与 contributor 心智负担。

其中 45 个交易所最近大概率不会使用（用户判断），继续留在维护清单中会持续产生上述成本。本迭代把 `去除清单.md` 列出的 45 个 submodule **从主仓库彻底移除**，并清理仓库内对它们的全部引用。

### 1.2 目标

1. **物理移除**：45 个 submodule 从 `.gitmodules` 注销、从 git index 移除、工作目录删除、`.git/modules` 本地元数据清理。移除后 `git submodule status --recursive` 只剩 15 个保留项。
2. **引用清理**：清除仓库中所有对 45 个交易所的活跃引用（代码、配置、脚本、示例、活跃文档）。
3. **历史归档清理**：历史归档（`docs/archive/`、`docs/plans/`、`docs/superpowers/`、`docs/迭代计划/迭代01`、`迭代02`、`docs/acceptance/2026-08-17-baseline-inventory.json`）中的相关痕迹一并摘除。
4. **可恢复留档**：在迭代文档中留档 45 个 submodule 的远端 URL 与移除时 pin 的 commit SHA，未来需要时可一条命令恢复。
5. **门禁零回归**：文档契约、交易所支持文档生成、submodule 校验配置、pytest 基线、`mkdocs build --strict` 全部保持通过。

### 1.3 保留清单（本迭代不动，共 15 个 submodule）

`bt_api_base`、`bt_api_binance`、`bt_api_bitget`、`bt_api_bybit`、`bt_api_coinbase`、`bt_api_ctp`、`bt_api_dydx`、`bt_api_gateio`、`bt_api_htx`、`bt_api_hyperliquid`、`bt_api_ib_web`、`bt_api_kraken`、`bt_api_mexc`、`bt_api_mt5`、`bt_api_okx`。

### 1.4 非目标（本期明确不做）

- **不删除远端 GitHub 仓库**（`github.com/cloudQuant/bt_api_<name>.git`）。远端仓库的去留属于组织级治理决策，本迭代只在留档表中记录 URL，供后续人工决定归档或删除。主仓库当前也不含这些仓库的 PyPI 发布凭据配置。
- **不删除已发布到 PyPI 的包**。已发布的 `bt_api_<name>` wheel 属于外部生态，本迭代不执行 yank。
- **不重构主包的插件发现机制**。`bt_api_py/_plugin_catalog.py`、`scripts/ci/submodule_validation.py`、`tests/test_repository_baseline.py` 均为动态发现（glob `bt_api/bt_api_*` 或读取 `.gitmodules`），删除后自动适配，无需改代码逻辑。
- **不修改 `docs/data/exchange_support_matrix.json`**。该文件是抽象 evidence tier（`core-reference bundle` / `other registered plugins`），不含具体交易所枚举。
- **不改动 `.gitignore` 的 `.gemini/`**。该条目是 Gemini CLI（AI 编码工具）缓存目录，与被移除的 Gemini 交易所无关。
- **不清理未被 git 跟踪的本地产物**（`.superpowers/`、`.joyincode/`、`.claude/`），它们不在仓库内容中。

## 2. 用户故事与场景

### US-1 维护者降低维护面

> 作为主仓库维护者，我希望维护清单只保留近期真正会用的交易所，这样 submodule 同步、pin 升级、诊断 CI 的成本与我的实际使用范围匹配。

### US-2 贡献者拿到干净仓库

> 作为贡献者，我 clone 仓库后不应该被 45 个用不上的 submodule 拖慢，也不应该在文档/脚本里看到指向这些 submodule 的死引用。

### US-3 未来可恢复

> 作为架构师，我需要一份完整留档，记录被移除 submodule 的仓库地址与移除时 pin 的 commit，这样将来要用某个交易所时能精确恢复到当时的版本。

### US-4 门禁不回归

> 作为 CI 维护者，移除后所有仓库既有质量门禁必须继续通过，且不能因为删了目录而出现"配置指向不存在的 submodule"这类悬空引用。

## 3. 功能需求

### FR-1 submodule 注销与移除

- 从 `.gitmodules` 删除 45 个 `[submodule "bt_api/bt_api_<name>"]` 段（含 `path`、`url`）。
- 执行 `git rm --cached`（或等价 `git update-index --force-remove`）从 index 移除 45 个 gitlink（mode `160000`）。
- 删除 45 个工作目录 `bt_api/bt_api_<name>/`。
- 删除 45 个本地 git 元数据目录 `.git/modules/bt_api/bt_api_<name>/`（`grep -r` 确认无 `core.worktree` 指向后按目录清理）。
- 保留 `.git/modules/bt_api/` 本身及 15 个保留项的元数据。
- 移除后 `.gitmodules` 只含 15 个 `[submodule]` 段，`git submodule status --recursive` 只含 15 行。

### FR-2 活跃代码与配置引用清理

逐文件清除对 45 个交易所的引用，且不引入悬空引用：

- `conftest.py`：`pytest_collection_modifyitems` 的 xdist 分组元组中移除 `bitfinex`、`kucoin`、`upbit`。
- `pyrightconfig.json`：`extraPaths` 移除 `./packages/bt_api_coinone/src`。
- `scripts/fix_plugin_entries.py`：`EXCLUDED` 集合移除 `bt_api_btbns`。
- `scripts/update_test_translator_imports.py`、`scripts/batch_delete_core_duplicates.py`、`scripts/batch_migrate_imports.py`：移除被删交易所的映射项。
- `scripts/extract_capabilities_v2.py`、`scripts/analysis/extract_capabilities_v2.py`：移除被删交易所条目。
- `_generate_docs.py`、`scripts/docs/generate_docs.py`：移除被删交易所定义。
- `scripts/run_exchange_tests.sh`、`scripts/testing/run_exchange_tests.sh`：用法帮助中的交易所示例清单只保留 15 个保留项。
- `scripts/run_base_tests.sh`、`scripts/run_optimized_tests.sh` 及其 `scripts/testing/` 副本：移除对 `gmx`、`poloniex`、`kucoin` 的引用。
- 上述文件改完后，全文再次扫描不得命中 45 个 token（`bt_api_<name>` 与裸 `<name>` 两种形式）。

### FR-3 活跃文档引用清理

- `bt_api/readme.md`：包状态清单删除被移除的 45 行，并修正总计口径。
- `docs/exchanges/EXCHANGE_STATUS.md`：删除被移除交易所的状态行与统计，口径与实际保留项一致。
- `docs/exchanges/EXCHANGE_CAPABILITY_MATRIX.md`：删除被移除交易所的能力行/列。
- `docs/CODE_QUALITY.md`：删除被移除交易所的条目。
- `docs/source-tree-analysis.md`：源码树中 `live_upbit/`、`live_kucoin/`、`live_bitfinex/` 等条目删除。
- 以上文档均为 `mkdocs.yml` 的 `exclude_docs` 覆盖范围或非站点页面，改动不得破坏 `mkdocs build --strict`。

### FR-4 示例清理

- 删除 `examples/network_tests/` 下全部被移除交易所专属测试文件（`test_<name>.py`、`test_live_<name>_request_data.py`、`feeds/<name>/`、`integration/test_<name>_integration.py`）。
- `examples/network_tests/README.md` 及混合文件中删除被移除交易所条目，保留保留项的说明。

### FR-5 历史归档清理

- **纯专属文件**直接删除，例如 `.superpowers` 未跟踪不处理；归档中形如 `docs/archive/迭代001/` 中整体面向被删交易所的段落做摘除。
- **混合文件**采用摘除式编辑（删除相关行/表行/列表项），保留其余历史内容：
  - `docs/acceptance/2026-08-17-baseline-inventory.json`（该文件同时含保留项与被删项）：删除被删项条目。
  - `docs/archive/agent_8_improvement_report.md`、`docs/archive/reports/comprehensive-improvement-plan.md`、`docs/archive/reports/improvement-report-v2.md`、`docs/archive/迭代001/研发TODO清单.md`。
  - `docs/plans/2026-03-08-junior-engineering-iteration-plan-phase-3.md`。
  - `docs/superpowers/plans/2026-08-16-remediation-iteration-plan.md`、`docs/superpowers/plans/2026-08-16-spec-analysis.md`、`docs/superpowers/plans/reports/2026-08-16-iter4.md`。
  - `docs/迭代计划/迭代02/完整迭代文档.md`、`docs/迭代计划/迭代02/研发TODO清单.md`。
- 历史归档改动不得改变其"历史证据"属性：仅摘除被删交易所引用，不新增结论。

### FR-6 留档

- 在 `研发设计文档.md` 或独立留档中给出：45 个 submodule 的 `path`、远端 `url`、移除时 pin 的 40 位 commit SHA。
- 给出恢复方法（`git submodule add <url> <path>` + `git -C <path> checkout <sha>`）。

## 4. 非功能需求

- **NFR-1 原子性**：submodule 移除与引用清理在同一批改动内完成，不留下"配置指向已删目录"的中间态。
- **NFR-2 可审计**：删除前的 pin SHA 全部留档，删除动作可由 git 历史回溯。
- **NFR-3 零门禁回归**：`python scripts/ci/check_docs_contract.py`、`python scripts/generate_exchange_support_docs.py --check`、`mkdocs build --strict`、`python -m pytest tests/ -q`（离线子集）均通过。
- **NFR-4 无残留**：全仓扫描（`研发设计文档.md` 第 2 节口径）对 45 个 token 的命中数，在排除"本迭代文档自身（留档表）"后为 0。
- **NFR-5 不引入新依赖**：仅删除与改写，不新增运行时依赖。

## 5. 约束与依赖

- Python 3.11–3.13 为阻塞 CI 目标（沿用 `docs/AGENTS.md` 约定）。
- 保留项中 `bt_api_ctp`、`bt_api_mt5` 含原生扩展，本迭代不触碰其构建。
- `.gitmodules` 是 `tests/test_repository_baseline.py` 的唯一真源，改它即改测试预期；该测试读 `.gitmodules` 而非硬编码，无需改测试代码。
- `scripts/ci/submodule_validation.py` 的 `experimental` profile 用 `discover_submodules=True` glob `bt_api/bt_api_*`，删除后自动收敛。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| `git rm --cached` 与工作目录删除顺序不当，残留 gitlink | index 与工作树不一致 | 先 `git rm --cached` 再删目录，最后校验 `git ls-files --stage \| grep 160000` |
| `.git/modules` 残留导致同名 path 重新 add 报错 | 未来恢复受阻 | 显式清理 45 个 `.git/modules/bt_api/<name>` 目录 |
| 历史归档改写破坏历史证据 | 审计链断裂 | 仅摘除引用行，不修改结论；保留文件其余原文 |
| 遗漏 `scripts/testing/` 下的重复脚本 | 双份残留 | 对同名脚本成对处理并复扫 |
| `gemini`/`buda` 等 token 误伤无关内容 | 误删 AI 工具缓存等其他含义 | 逐处人工甄别：`.gitignore` 的 `.gemini/` 明确保留 |
| 删除 examples 测试后 pytest 收集失败 | CI 红 | 删除后跑 `pytest --collect-only` 与全量离线测试 |
