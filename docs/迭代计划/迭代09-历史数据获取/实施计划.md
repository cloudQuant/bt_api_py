## 1. 全局约束

1. **合规硬约束**：不得复制 OpenBB 源码（AGPL）；akshare 搬运必须保留 MIT 声明与来源 commit；
   整合后运行时不依赖 `akshare` / `openbb`（CI 断言）。
2. **不改迭代04/06 采集链路**；`download_history_bars` 对外行为不变（回归保护）。
3. **分批交付**：任何单一里程碑不得试图"一次搬完/一次做完"；每个 Task 必须可独立验证。
4. **搬运可重跑**：codemod 幂等，人工修改文件登记在 `ported.lock`，不被覆盖。
5. **默认保守**：并发/QPS/重试默认值不触发上游限流。
6. 文档、测试与代码同步提交；`bt_api_data` 内每个包都必须有 README 与 pyproject（可独立安装）。
7. **`.gitmodules` 只新增 1 项**（`bt_api_data`）；禁止把数据源包直接放进 `bt_api/` 目录。

## 5. 已知限制

- **搬运代码的隐性缺陷**：10.5 万行机械化改写后，未被对照覆盖的冷门接口可能带缺陷；
  因此对照覆盖度按 P0 域"逐接口"、冷门域"每模块抽样"。
- **爬虫可用性随时间衰减**：上游站点改版会导致部分接口失效，属预期；
  同步工具与失败分类是缓解手段，不是保证。
- **商业源能力受限**：未配置 Key 的 provider 只有接口与契约测试，无真实数据验证。
- **P2 provider 结构特殊**（sec 的 XBRL/分页、congress_gov 的批量文件）：
  实现成本高于模板预期，必要时拆分为子任务并在 README 标注 experimental。
- **本迭代不产出落库方案**：数据保存由使用方代码决定（用户明确）。
