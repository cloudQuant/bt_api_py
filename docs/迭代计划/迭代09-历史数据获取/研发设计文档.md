## 1. 设计目标与原则

### 1.1 目标

在 `bt_api_py` 内建立**统一的历史数据获取层**：

1. `bt_api_http`：**源码级全量搬运** akshare（MIT），移除对 akshare 包的运行时依赖；
2. `bt_api_fuyao`：自建同花顺扶摇 API 客户端，覆盖全部端点；
3. `bt_api_<provider>`：按 OpenBB 的 32 个 provider **自研**等价实现（**零 OpenBB 源码**）；
4. 统一入口收敛在 `BtApi`：`资产类别 × 数据域 × 数据源` 的路由与降级；
5. 整合完成后，运行时不依赖 `akshare` / `openbb`。

### 1.2 设计原则

1. **合规优先**：许可证边界是硬约束，不是可以变通的建议（见 §1.3）。
2. **搬运最大化机械改写**：akshare 内部导入形态极其规整（602 处绝对导入、仅 1 处相对导入），
   搬运应尽量由工具完成、人工只处理例外，降低 10.5 万行规模的人工成本与出错率。
3. **契约先于实现**：先定标准化模型与数据源协议，再让三个来源去适配；`BtApi` 只依赖契约。
4. **包即插件**：每个数据源是一个独立可安装的包（位于 `bt_api_data/packages/`，沿用既有
   `bt_api_*` 命名惯例），可单独测试与发布。
5. **默认保守**：并发/重试/缓存默认值以"不触发上游限流、不制造压力"为准，可显式放开。
6. **可追溯**：搬运代码保留来源标注与上游 commit；自研代码保留接口对照表但无源码参照。

### 1.3 合规边界（AGPL 隔离机制）★

| 来源 | 许可证 | 允许动作 | 禁止动作 |
|------|--------|---------|---------|
| akshare | MIT | 复制/修改/再分发（保留版权与许可声明） | 去除版权声明 |
| OpenBB | **AGPL-3.0** | 参考**接口形态、命名、文档描述**（事实性契约） | **复制任何源码**（含改名/换序等改写） |
| 同花顺扶摇 | 商业服务 | 按其 API 契约调用 | 绕过认证/超限使用 |

**OpenBB 自研的可执行判据**（写入 code review 清单）：

1. 实现文件**不得**引用 OpenBB 仓库路径、不得出现其源码片段或注释；
2. 允许参照：端点路径、参数名、字段名、响应结构等**接口契约**（属事实信息），
   以"接口对照表"（§6.3）形式落档，不附源码；
3. 每个 provider 的 PR 必须声明"无 OpenBB 源码参照"，并在 `THIRD_PARTY_NOTICES.md` 中
   记录"仅参考接口文档，未复制代码"；
4. CI 增加**源码相似度扫描**（对 OpenBB 仓库做 n-gram/行级相似检测），阈值超标即失败。

### 2.3 与既有插件体系的关系

现有机制面向**交易/行情连接**：entry point 组 `bt_api.plugins` →
`register_plugin(registry: ExchangeRegistry, runtime_factory)` →
`register_feed / register_exchange_data / register_balance_handler / register_stream`，
并由 `bt_api_py/configs/exchange-bundles.toml` 做安装/认证状态目录。

数据源与交易网关**关注点不同**（无 feed/stream/balance，只有"查询能力"），因此：

- **新增独立注册通道**：entry point 组 `bt_api.data_sources`
  ```toml
  [project.entry-points."bt_api.data_sources"]
  http = "bt_api_http.plugin:register_data_source"
  fuyao = "bt_api_fuyao.plugin:register_data_source"
  yfinance = "bt_api_yfinance.plugin:register_data_source"
  ```
- **不改 `bt_api_base` 的 `ExchangeRegistry`**（该包为独立 submodule，避免跨仓联动阻塞本期）。
- **新增数据源目录** `bt_api_py/configs/data-sources.toml`，供 `doctor`/CI 报告
  每个数据源的安装状态、能力覆盖与 Key 是否就绪（与 `exchange-bundles.toml` 平行）。
- 同一个包**可以两者都注册**（例如未来 `bt_api_fuyao` 若提供实时行情），
  但本期数据源包只注册数据源。

## 3. 统一数据契约（`bt_api_py/data/`）

### 3.1 标准化数据模型

以 `pydantic` 定义（主包已依赖 pydantic v2），每个模型提供 `to_dataframe()` 与 `from_raw()`：

| 模型 | 关键字段 | 覆盖需求 |
|------|---------|---------|
| `Bar` | symbol, market, period, datetime, open/high/low/close, volume, amount, open_interest, adjust, source | 行情（股/期/基金/期权/加密/海外） |
| `Quote` | symbol, datetime, last, bid/ask, volume, ... | 快照 |
| `AdjustFactor` | symbol, ex_date, factor, cash_dividend, split_ratio | 复权因子 |
| `CorporateAction` | symbol, ex_date, kind(dividend/split/rights), payload | 除复权事件流 |
| `FinancialStatement` | symbol, statement(income/balance/cashflow), period, report_date, items | 三大报表 |
| `FinancialIndicator` | symbol, period, category(growth/profit/solvency/operation/cashflow), items | 财务指标 |
| `IndexConstituent` | index, symbol, as_of, weight, in_date, out_date | 指数成分 |
| `MacroSeries` | series_id, datetime, value, unit, source | 宏观序列 |
| `FuturesFundamental` | symbol, kind(position/warehouse/basis/profile), datetime, payload | 期货基本面 |
| `OptionContract` / `OptionBar` | symbol, underlying, strike, option_type, expiry, quote/bar | 期权 |
| `FundNav` / `FundHolding` | symbol, datetime, nav/acc_nav, holdings | 基金 |

约定：`datetime` 统一为**带时区的 ISO/UTC**（沿用 `data_downloader._parse_time` 的既有语义：
naive 输入按 UTC 解释）；数值列缺失用 `None` 而非 `NaN` 字符串；`source` 字段始终回填
（可追溯"这条数据来自哪个源"）。

### 3.2 数据源协议（三段式，借鉴 OpenBB 范式、自研实现）

```python
class QueryParams(BaseModel):
    """一次查询的参数（可被缓存键序列化）。"""

class Fetcher(ABC):
    """数据域抓取器：一个 (资产类别, 数据域) 一个类。"""

    capability: Capability

    @abstractmethod
    def transform_query(self, **kwargs) -> QueryParams: ...
    @abstractmethod
    def extract_data(self, params: QueryParams, ctx: FetchContext) -> Any: ...
    @abstractmethod
    def transform_data(self, raw: Any, params: QueryParams) -> list[Bar] | list[...]: ...

class DataSource(ABC):
    """一个数据源的注册单元：声明能力 + 提供 fetcher。"""

    source_id: str                     # "http" | "fuyao" | "yfinance" | ...
    display_name: str
    license_notice: str
    def capabilities(self) -> list[Capability]: ...
    def get_fetcher(self, capability: Capability) -> Fetcher: ...
    def check(self) -> HealthStatus: ...   # Key 是否配置、端点是否可达
```

`FetchContext` 携带 HTTP 客户端、缓存、限流器、日志与取消信号，使 fetcher 不直接触达网络栈。

### 3.3 能力声明

```python
@dataclass(frozen=True)
class Capability:
    asset: str        # equity | future | option | fund | index | crypto | forex | macro
    domain: str       # price | adjust | corporate_action | financials | indicators
                      # | constituents | macro | fundamentals | nav | quote
    market: str       # cn | hk | us | global
    periods: tuple[str, ...] = ()     # 复用既有周期词表 1m/5m/15m/30m/1H/1D/...
    adjust: tuple[str, ...] = ()      # ("", "qfq", "hfq")
    notes: str = ""
```

`Capability` 同时是**路由键**与**覆盖度报告单元**（`describe_data_source()` 输出）。

### 3.4 注册表与路由

```python
class DataRegistry:
    def register(self, source: DataSource) -> None: ...
    def sources(self) -> list[str]: ...
    def find(self, capability: Capability) -> list[DataSource]: ...   # 按优先级

class DataRouter:
    """按 (asset, domain, market) 选源，失败可降级。"""

    def resolve(self, capability: Capability, source: str = "auto") -> list[DataSource]:
        """source=auto → 配置优先级序；显式 source → 只返回该源（不可用则报错）。"""
    def execute(self, capability, request, *, source="auto", allow_fallback=True) -> Result:
        """依次尝试候选源；记录每次尝试的源与失败原因。"""
```

路由优先级声明在 `bt_api_py/configs/data-routing.toml`（可被用户配置覆盖）：

```toml

[domains."equity.price.minute.cn"]
sources = ["http", "fuyao"]          # 分钟线 akshare 覆盖更全
[domains."equity.adjust.cn"]
sources = ["fuyao", "http"]
[domains."equity.financials.cn"]
sources = ["fuyao", "http"]
[domains."index.constituents.cn"]
sources = ["fuyao", "http"]
[domains."future.price.cn"]
sources = ["fuyao", "http"]
[domains."future.fundamentals.cn"]
sources = ["fuyao", "http"]
[domains."equity.price.us"]

[domains."macro.global"]

```

### 3.5 `BtApi` 数据入口

```python
# 行情
```

- **向后兼容**：既有 `download_history_bars(exchange_name, symbol, ...)` 保持原语义不变；
  其内部可改为走新路由（当 `exchange_name` 能映射到数据源时），但签名与行为契约不变。

- **异常**：统一 `DataSourceError` 家族（`SourceUnavailableError` / `CapabilityNotSupportedError` /

> 独立 `pyproject.toml`，可单独 `pip install -e packages/bt_api_http`，依赖互不干扰；
> ③ 共享工具（codemod、上游同步、对照）只需一份。

### 4.2 搬运改造规则

实测 akshare 内部导入形态（这决定了搬运成本）：

| 事实 | 数量 | 对搬运的意义 |
|------|------|-------------|
| `from/import akshare...` 绝对导入 | **602 行** | 机械前缀替换即可 |
| 相对导入（`from .`） | **1 行** | 几乎无需处理 |
| `import akshare as ak` 自引用 | **0** | 无循环自引用风险 |
| 第三方依赖 | requests 354 / pandas 339 / urllib3 68 / bs4 50 / mini-racer 40 / … | 依赖清单明确（§4.4） |

**改写规则（codemod 逐条落实）**：

1. `from akshare.X import Y` → `from bt_api_http.X import Y`；`import akshare.X` → `import bt_api_http.X`
   （前缀替换，602 处）。
2. 顶层 `akshare/__init__.py`（5954 行聚合导出）→ `bt_api_http/__init__.py`，
   保持同名导出集合，使 `bt_api_http.<fn>` 与 `akshare.<fn>` 一一对应。
3. 请求层收口：`akshare/request.py`、`akshare/utils/request.py` 及各文件内的
   `requests.get/post` 直连 → 统一走 `bt_api_http.http.Client`（§4.3）；
   保留原有站点专用函数名（`request_eastmoney` 等）作为薄封装，避免大范围改动。
4. 去掉 akshare 特有的打印/进度条耦合：`tqdm`（`get_tqdm`）保留但可被 context 关闭
   （批量任务下静默，避免 10 年全市场刷屏）。
5. 异常规范化：akshare 内部 `raise RuntimeError(f"...")` 保留原样，但**公开 API 出口**
   统一包装为 §3.5 的异常家族（不改公开函数签名，只在 fetcher 层包装）。
6. 文件头版权：保留原 `Date/Desc/URL` 注释，追加搬运标注（见 §4.6）。
7. 不做"顺手重构"：搬运文件保持与上游尽可能一致，便于日后 diff 同步（§7）。

**公开 API 命名（已决策，2026-09-19）**：

- `bt_api_http` 的公开函数**沿用 akshare 原名**（`stock_zh_a_hist`、`futures_zh_daily_sina`、
  `index_stock_cons_csindex`…），**但不再带 `akshare` 前缀**——它们位于 `bt_api_http`
  命名空间下，调用形态是 `bt_api_http.stock_zh_a_hist(...)`。
- 理由：① 与 akshare 官方文档/社区示例可逐字对应，降低使用与排障成本；
  ② 上游同步时函数名可比对，diff 噪音最小；③ 搬运保真对照（§9 L1）可直接同名调用两侧。
- 语义化入口由上层提供：`BtApi` 的 `get_history(...)` 等按"资产 × 数据域"封装，
  内部路由到 `bt_api_http.stock_zh_a_hist` 之类的原函数——**底层保真可追溯，上层语义统一**。
- `bt_api_fuyao` 与 32 个 provider **不套用** akshare 命名，直接采用 `bt_api` 风格的
  资源名（与 `BtApi` 入口和接口对照表对齐）。

### 4.3 HTTP 客户端与请求治理

`bt_api_http/http/client.py`（也可被其它源复用，实现放在主包 `bt_api_py/data/http/`）：

- 会话复用（`requests.Session`）+ 连接池；UA/Referer 可配；
- 超时（连接/读取分别可配，默认保守）；
- 重试：指数退避 + 抖动，仅对幂等 GET；
- **限流**：按 `(host)` 令牌桶（默认低 QPS，可配），429/403 触发退避与熔断标记；
- 失败分类：网络 / 超时 / 限流 / 反爬（HTML 结构变化）/ 上游错误，产出可诊断信息；
- 可选缓存（§8）；
- 代理支持（海外源必需）。

> 设计取舍：**不在本期引入 playwright/无头浏览器**。akshare 现有接口中依赖
  `py_mini_racer`/`mini-racer` 的 JS 解密保留（依赖已声明），
  浏览器渲染类站点若确有缺失，列入开放问题 §12。

## 5. `bt_api_fuyao` 设计（同花顺扶摇 API）

### 5.1 客户端与协议

- Base URL：`https://fuyao.aicubes.cn`；认证头 `X-api-key`（**来自环境变量/配置，不硬编码**）。
- 统一信封解析：
  ```
  { "code": 0, "message": "success", "request_id": "...", "data": { "timestamp": ..., "item": [...] } }
  ```
- 客户端职责：URL/参数拼装（`thscode` 规范化：股票/指数/基金必须带后缀如 `600519.SH`）、
  `code` 判定、`data.item` 提取、`request_id` 留痕、时间戳（毫秒、`Asia/Shanghai`）标准化。
- 配置：`FUYAO_API_KEY`、可选 `FUYAO_BASE_URL`、超时、QPS 上限、重试次数。

### 5.2 错误码与限流

| code | 含义 | 客户端行为 |
|------|------|-----------|
| 0 | 成功 | 返回 |
| 1001 / 1002 / 1003 / 1004 | 参数类（缺参/格式/越界/冲突） | 抛 `RequestParamError`，**不重试**；1003 的"历史窗口超限"由上层自动**分段** |
| 2001 / 2003 | 未认证/无权限 | 抛 `AuthError`，提示配置 Key/权限，不重试 |
| 3001 / 3002 / 3004 | 标的不存在/数据未就绪/类型不支持 | 3002 可退避重试（数据未就绪）；3001/3004 直接报错 |
| 4001 | 频率超限（对应 HTTP 429） | 退避重试（指数退避 + 抖动），并降低全局 QPS |
| 5001 / 5002 / 5003 | 服务端/上游问题 | 有限重试；连续失败进入熔断冷却 |

### 5.3 端点分组与模型映射

按官方文档分组实现（每组一个 fetcher，映射到 §3.1 模型）：

| 文档分组 | 端点前缀 | 映射模型 |
|---------|---------|---------|
| 基础 | `/api/meta/tickers/search`、`/api/meta/tickers/list`、`/api/a-share/calendar` | 元信息 / 交易日历 |
| A股行情 | `/api/a-share/prices` | `Bar` / `Quote` |
| 全市场导出 | `/api/dump/market-dumps` | `Bar` / `AdjustFactor`（Parquet，§5.4） |
| 除复权 | `/api/a-share/corporate-actions` | `AdjustFactor` / `CorporateAction` |
| 财务 | `/api/a-share/financials`、`/api/a-share/financials/indicators` | `FinancialStatement` / `FinancialIndicator` |
| 指数 | `/api/a-share-index` | `IndexConstituent` |
| 估值 / 竞价 / 资金 / 高频 / 特色 | `/api/a-share/{valuations,auction,capital-flow,high-frequency,special-data}` | 对应模型 |
| 期货 | `/api/futures`、`/api/futures/fundamentals`、`/api/futures/calendar/session-timeline` | `Bar` / `FuturesFundamental` |
| 期权 | `/api/options`、`/api/options/calendar/session-timeline` | `OptionContract` / `OptionBar` |
| 基金 | `/api/fund`、`/api/fund/{backtest,indicators,quota}` | `FundNav` / `FundHolding` |

> 文档中标注"计划在后续版本接入同花顺AI客户端、当前暂不可用"的能力（capital-flow / high-frequency /
> 期货扩展资料 / 期货 F10 / 交易时间轴等）**统一登记为 `Capability(notes="upstream-pending")`**：
> 接口实现先行、能力声明标注为不可用，避免路由误选。

### 5.4 Market Dumps（全市场 10 年日 K + 复权因子）

- 走 `/api/dump/market-dumps`（`X-api-key` 入口），拿到 Parquet 文件下载链接；
- 下载到缓存目录，校验（大小/可读/行数）后解析为标准模型；
- 这是"全市场 10 年日线 + 复权因子"的**首选路径**（一次拉取替代逐标的数万次请求），
  路由优先级最高；解析结果可直接喂给批量任务（§8）。

### 5.5 配置与凭证

- `FUYAO_API_KEY` 从 `.env`/环境读取（沿用 `bt_api_py` 既有 `python-dotenv` 机制）；
- 缺失 Key 时：`check()` 返回未就绪，路由**自动跳过该源**并降级（不报错中断）；
- 请求日志脱敏（不打印 Key）。

## 7. 上游同步机制

- `bt_api_http/upstream.lock`：
  ```toml
  [upstream]
  repo = "https://github.com/akfamily/akshare"
  commit = "<40位 sha>"
  ported_at = "2026-09-19"

  [files."src/bt_api_http/utils/func.py"]
  upstream = "akshare/utils/func.py"
  sha256 = "..."
  manual_edits = false
  ```
- `scripts/codemod/fetch_upstream.py --diff`：拉取上游新版本，输出
  "新增 / 修改 / 删除"清单与**关键函数签名 diff**（不解析实现差异，避免噪音）。
- 同步流程写入运维文档：`diff → 评估 → port_module 重跑（跳过 manual_edits）→ 对照 → 提交`。
- 同花顺：记录文档抓取日期与端点清单快照，端点变更时更新映射表并 bump 版本。

## 8. 缓存与增量

- **缓存根**：`BT_API_CACHE_DIR`（默认 `~/.cache/bt_api_py`；Windows 用 `%LOCALAPPDATA%`）。
- **缓存键**：`source + capability + 规范化参数 + 数据版本`；值存原始响应或标准化结果（parquet/json）。
- **不可变区间策略**：历史日线中"已收盘且早于今天"的区间视为不可变 → 允许长期缓存；
  当日数据不缓存（或极短 TTL）。
- **批量与续拉**：
  ```python
  api.fetch_many(
      requests=[FetchRequest(...), ...],
      concurrency=4, cache=True,
      progress_file="<cache>/tasks/<task_id>.json",
      on_error="continue",           # 单标的失败不阻断
  ) -> FetchTaskResult(succeeded, failed, skipped, failures_path)
  ```
  进度文件记录每个标的的状态（pending/done/failed），重跑时跳过 done（幂等）。
- **限流联动**：缓存命中不发请求；批量任务按源 QPS 令牌桶节流。

## 9. 数据质量对照设计

三层对照，各自有明确的证据形式：

| 层 | 对象 | 方法 | 证据 |
|----|------|------|------|
| L1 搬运保真 | `bt_api_http` vs akshare | **录制回放**：录制上游 HTTP 响应为 fixture，同一 fixture 分别喂给两者，比对返回 DataFrame 的**列集合、dtypes、行数、主键排序**；关键数值列抽样比对 | `tests/contract/compare_*.py` + 对照报告 |
| L2 权威源 | `bt_api_fuyao` vs 官方 | 用文档示例请求与 Market Dumps Parquet 对照；字段/单位/时间戳口径逐项核对 | 真机联调记录（Key 已有） |
| L3 自研 provider | provider vs 上游官方输出 | 以 `yfinance` 官方 `download()`、FRED 官方 CSV 为基准，逐字段比对 | `tests/contract/compare_provider_*.py` |

- **实时数据漂移**：L1/L3 一律用录制样本或固定历史区间，避免"数据本身在变"导致误判；
  差异容忍度（如浮点尾差 1e-6、行数 ±0）在验收文档中明确。
- **对照是开发期能力**：需要安装 akshare/openbb 等上游包，声明在 `[project.optional-dependencies] dev`，
  CI 中标记为 `contract` 测试，缺失依赖时 skip。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| **AGPL 污染** | 高（法律） | 零源码复制 + CI 相似度扫描 + PR 声明留档（§1.3） |
| akshare 全量搬运 10.5 万行引入隐性缺陷 | 高 | 机械改写 + 分模块递进 + 录制回放对照 + 保留上游 diff 能力 |
| 爬虫站点改版导致接口失效 | 高（常态） | 上游同步机制 + 失败分类可诊断 + 能力声明可标注失效 |
| 上游接口限流/封禁（akshare 站点） | 中 | 默认低 QPS 令牌桶 + 缓存 + 批量任务节流 |
| 同花顺 Key 限流（429/4001）与窗口上限（1003） | 中 | 退避重试 + 自动分段 + 路由降级到 akshare |
| 规模过大导致长期不可交付 | 高 | 强制分批（P0/P1/P2）+ 每批可独立验收（§6.2、实施计划） |
