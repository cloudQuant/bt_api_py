# Local CTP Gateway profile (native writes disabled)

`ctp-local-readonly` is an installed Gateway operator profile for a protected local resource file. It is not a trading or settlement-confirmation profile: native writes and automatic settlement confirmation are disabled, and admission always fails. CTP connection itself can still contact the configured venue when the service is started; do not run it against an account without separate authorization. The existing builder requires `dispatch_enabled: true`; this exposes a dispatch endpoint, while native admission remains denied. Authorized logical commands can still create local journal records.

The accompanying YAML and JSON are incomplete examples, not operational credentials or grants. Copy the JSON into an operator-owned private directory (mode 0700) as an operator-owned regular file (mode 0600, one hard link). Replace all placeholders with explicitly provisioned values. Symlinks are rejected in the path, and unsafe ancestor permissions are rejected. This loader currently supports POSIX only and does not audit filesystem ACLs. Protect the file using appropriate host controls as well.

Set `BT_API_CTP_GATEWAY_RESOURCES_FILE` to the absolute path of that private file and pass the YAML to `bt-gateway-operator --config PATH`. The installed wheel must contain the `ctp-local-readonly` profile entry point and its optional CTP, Gateway and ZMQ dependencies must be installed. YAML declares topology only; authority, client CURVE public keys, server CURVE key pair, identity, account and operation grants come exclusively from the protected file. Its supplied client grant is limited to command-status reads; authorize additional operations only deliberately. The example `market: null` provides no market stream.

The CTP `broker_id` and `user_id` must match `settings.account_key.subaccount_id` and `account_id`. Set every account scope to that exact AccountKey's `account_key_id`. Paths must refer to the intended protected guard, flow and existing journal resources; the expected journal ID and revision must match the independently provisioned journal. Preserve an existing journal and owner fence, and do not invent them from the sample. The example is not a journal provisioning or recovery procedure. The current direct CTP credential-binding verifier depends on the retired runtime review adapter, so these files do not establish the trust needed to enable real trading.
