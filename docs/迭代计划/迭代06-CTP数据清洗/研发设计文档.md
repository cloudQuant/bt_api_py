## 1. 设计目标与原则

### 1.1 目标

在 `bt_api_ctp` 内实现一套**每日盘后数据清洗管道**：从多台远程服务器
（Linux + Windows 混合）拉取迭代04 落盘的 tick 数据，校验后与本地权威库
合并去重，安全回收远程已合并数据，并将 tick 合成为 1/5/15 分钟 K 线。

### 1.2 设计原则

1. **只读复用迭代04**：不改 `collector/`、`collector_ctp/` 任何代码；
   合并去重/原子写直接 import `collector.sink` 的既有原语，不复制实现。
2. **先校验后动作**：删除远程数据只能发生在"verified + merged"之后；
   任何不确定状态都停在安全侧（保留数据 + 报告告警）。
3. **全流程幂等**：每个阶段可独立重跑；重跑不产生重复数据、不误删。
4. **本地是唯一权威库**：远程数据合并进 `ctp_data` 后，本地即全量；
   staging 只是过渡区。
5. **K 线聚合与交易所解耦**：聚合器只依赖通用 tick schema；交易所特有的
   品种命名规则独立成可插拔规则表（`cleaner_ctp/symbols.py`）。

## 3. 核心接口设计

### 3.1 PullBackend（传输后端协议）

```python
@dataclass(frozen=True)
class RemoteFile:
    rel_path: str      # 相对 remote_data_root，如 "20260918/SHFE/rb2510.parquet"
    size_bytes: int

class PullBackend(Protocol):
    name: str
    def check(self) -> None:
        """连通性检查（check-hosts 用）。"""

    def list_days(self) -> list[str]:
        """列出 remote_data_root 下全部 trading_day 目录名（YYYYMMDD）。"""

    def list_day_files(self, day: str) -> list[RemoteFile]:
        """列出某 trading_day 目录内的最终落盘文件
        （各交易所 *.parquet + report.json；排除 *.lock 与 staging 段文件）。"""

    def fetch_day(self, day: str, dest: Path) -> FetchResult:
        """把该目录全部文件拉到 dest/<day>/（增量、幂等：
        已存在且字节数一致的文件跳过）。返回传输统计。"""

    def delete_day(self, day: str) -> None:
        """删除远程该 trading_day 目录（调用方已做三重保护校验）。"""

    def close(self) -> None: ...
```

三个实现：

| 后端 | 实现 | 适用 | 要点 |
|------|------|------|------|
| `rsync` | `subprocess` 调系统 `rsync -a --info=stats2` + `ssh` | Linux 服务器 | `--exclude '*.lock' --exclude 'staging*' --exclude '*.tmp'`；天然增量续传；`--stats` 取传输统计；删除走 `ssh host rm -rf <root>/<day>`（路径先经白名单校验） |
| `sftp` | `paramiko`（依赖引入见开放问题 1） | Windows 服务器（Linux 亦可用） | 递归 listdir 构建清单；按 size 跳过已传文件；分批 get；删除走 `sftp.remove` 逐文件 + `rmdir` 自底向上 |
| `local` | 本地路径直接复制 | 测试、首次手工迁移 | 同一接口，`shutil` 实现；全部集成测试在本地完成，不打真实网络 |

> 设计约束：`cleaner/pull/` 内不得 import 任何 CTP 专属模块；
> 后端只认"迭代04 目录规范"，与交易所无关。

### 3.2 Manifest（拉取状态档案）

落盘 `<tick_root>/cleaner/manifest.json`，原子写（tmp + rename）：

```json
{
  "version": 1,
  "hosts": {
    "server-a": {
      "20260918": {
        "status": "merged",
        "files": [
          {"rel_path": "20260918/SHFE/rb2510.parquet", "size_bytes": 123456, "rows": 45678}
        ],
        "pulled_at": "2026-09-19T16:00:31+08:00",
        "verified_at": "2026-09-19T16:02:11+08:00",
        "merged_at": "2026-09-19T16:05:47+08:00",
        "deleted_at": null
      }
    }
  }
}
```

状态机：

```
discovered → pulled → verified → merged → deleted
     └──────────┴─────────┴────────→ failed（带 error 信息，可重试回到上一成功态）
```

- 每次阶段推进即落盘 manifest（崩溃后从最后状态续跑）。
- `deleted` 是终态；已 deleted 的目录若远程再次出现（远程误重传），视为新目录重新走流程。
- 删除决策**只**依据 manifest 中 `merged` 状态，不依赖内存。

### 3.3 合并接口（复用迭代04 原语）

```python
# collector/sink.py 既有原语（直接 import，不复制）：
#   _dedup_sort(rows)      按 (action_day, update_time, update_millisec) 排序，
#                          同键保留 local_receive_time 最新
#   _read_existing(path)   读已有 parquet 为 rows
#   _write_atomically(path, rows)  临时文件 + rename 原子替换

def merge_instrument(target: Path, sources: list[Path]) -> MergeStat:
    """把 sources（各机器 staging 中同一合约文件）合并进 target：
    rows = target(若存在) + sources 全部
    → _dedup_sort → _write_atomically 覆盖 target
    返回 {added, deduped, total}。逐合约调用，内存只承载单合约。"""
```

- 合并单位是**单合约文件**（`<day>/<exchange>/<instrument>.parquet`），
  staging 中多机器的同名文件 + 权威库现有文件三者拼接去重。
- 权威库 schema 不变；若 staging 文件 schema 与权威库不一致（远程老版本采集），
  以字段名对齐后合并，缺列按 null 填充并告警（防御性，正常不应发生）。

### 3.4 K 线聚合器

```python
@dataclass(frozen=True)
class Bar:
    datetime: int          # 桶起始 epoch ns（交易所本地时间，naive）
    open: float
    high: float
    low: float
    close: float
    volume: int            # 桶内成交量（累计差分）
    amount: float          # 桶内成交额（累计差分）
    open_interest: float   # 桶末持仓量
    trading_day: str
    instrument_id: str
    exchange_id: str

def aggregate_1min(rows: list[dict]) -> list[Bar]:
    """tick rows（已排序）→ 1 分钟 Bar 列表。"""

def aggregate_from_1min(bars: list[Bar], minutes: int) -> list[Bar]:
    """1 分钟 Bar → 5/15 分钟 Bar（OHLC 首开末收、量额求和、持仓取末）。"""
```

聚合规则（关键语义，均有单测锁定）：

1. **时间戳构造**：`datetime = action_day + " " + update_time` 补毫秒 →
   按交易所本地时间解析为 naive `timestamp[ns]`；桶键 = `ts - ts % (60s × N)`
   （**钟面对齐**：09:00:00–09:00:59 归 09:00 桶；夜盘跨零点自然分桶）。
2. **OHLC**：桶内按时间序，`open`=首条有效价、`close`=末条有效价、
   `high`/`low`=有效价最大/最小；"有效价"= `last_price` 为正且有限
   （CTP 停牌/异常快照可能为 0 或 inf，过滤）。
3. **volume / amount 差分**：`v = 桶末累计 − 桶前一条 tick 累计`
   （桶前一条 = 全序中该桶首条的前一条 tick）；
   - 前一条不存在（当日首桶）→ `v = 桶末累计 − 0`；
   - 差为负（跨交易日累计清零）→ 改用 `桶末 − 桶内首条`；仍为负 → 钳 0 并告警。
   - `amount` 对 `turnover` 同法。
4. **open_interest**：桶内末条值（快照字段，非累计，直接取末）。
5. **非交易时段**：无 tick 即无桶，不造空桶；小节休息前后桶不连续是预期行为。
6. **5/15 分钟**：仅从 1 分钟聚合，保证 `sum(1min.volume) == 5min.volume`
   可验证自洽。

### 3.5 品种规则表（cleaner_ctp/symbols.py，CTP 专属）

```python
# 按交易所注册 (期权模式, 期货模式)；期权优先匹配（含 C/P 标记，先于期货命中）
SYMBOL_RULES: dict[str, dict[str, re.Pattern]] = {
    # SHFE / INE：rb2510C3200 / sc2510P600 ｜ 期货 rb2510
    "SHFE": {"option": r"^([a-z]{1,2})\d{3,4}[CP]\d+$", "future": r"^([a-z]{1,2})\d{3,4}$"},
    "INE":  {"option": r"^([a-z]{2})\d{3,4}[CP]\d+$",    "future": r"^([a-z]{2})\d{3,4}$"},
    # DCE / GFEX：m2509-C-3000 ｜ 期货 m2509、si2512
    "DCE":  {"option": r"^([a-z]{1,2})\d{1,4}-[CP]-\d+(\.\d+)?$", "future": r"^([a-z]{1,2})\d{1,4}$"},
    "GFEX": {"option": r"^([a-z]{2})\d{3,4}-[CP]-\d+$",  "future": r"^([a-z]{2})\d{3,4}$"},
    # CZCE：SR509C5000（3 位月份）｜ 期货 SR509
    "CZCE": {"option": r"^([A-Z]{1,2})\d{3}[CP]\d+$",    "future": r"^([A-Z]{1,2})\d{3}$"},
    # CFFEX：IO2509-C-4000（股指期权品种 IO 自成品类）｜ 期货 IF2509 / T2509

def extract_symbol(exchange_id: str, instrument_id: str) -> str | None:
    """返回品种代码（期权返回标的品种；CFFEX 股指期权返回期权品种本身如 IO）；
    无法匹配返回 None（调用方记告警清单、跳过 K 线合成）。"""
```

- 期权归入标的品种目录（`m2509-C-3000` → `DCE/m/`）；CFFEX 股指期权
  `IO/MO/HO` 自成品类目录（标的为指数无指数目录，归指数代码目录 `CFFEX/IO/`）。
- **实施期校准动作（必做）**：用本地已有真实落盘合约清单
  （20260917/20260918/20260921 三日全部文件名）跑规则表，
  要求**识别率 100%**；识别不了的进 `unknown` 清单后再修规则，
  不得静默丢弃。

## 4. 关键流程设计

### 4.1 每日 run（默认一条龙）

```
1. 加载 cleaner.yaml；非交易日 → exit 3
2. 获取进程锁（<tick_root>/cleaner/cleaner.lock；已有实例则告警退出）
3. 磁盘空间预检：Σ(各机器待拉清单字节数) × 1.2 > 可用空间 → 告警 exit 2
4. 对每台机器（顺序执行，可配置并发）：
   a. list_days() → 过滤：manifest 已 deleted 的跳过；无 report.json 的跳过（未完成）
   b. fetch_day(day, staging) → manifest: pulled
   c. 三级校验（清单/字节/可读+行数）→ manifest: verified；失败 → failed + 告警，跳过后续
5. merge：对 staging 内每个 (day, exchange, instrument)：
   merge_instrument(ctp_data/<day>/<ex>/<inst>, [staging 各机同路径]) → manifest: merged
6. delete（若开启）：对 manifest 中 merged 且未 deleted 的目录：
   白名单校验（remote_data_root 前缀 + YYYYMMDD 格式）→ delete_day() → manifest: deleted
7. kline：对本次合并涉及（或指定）的 trading_day 逐日合成 → kline_root
8. 写清洗报告；释放锁；退出码按 FR-8
```

> staging 清理：merge 成功后该 day 的 staging 临时目录可删除（保留亦可，
> 下次 fetch 会按 size 跳过；默认删除以控磁盘）。

### 4.2 与迭代04 采集的时序兼容（16:00 安全性论证）

```
T-1 日 21:00 ──夜盘──> T 日 02:30   ┐
T 日 09:00 ──白盘──> 15:15          ├─ 全部写入 ctp_data/T/（trading_day=T）
15:15 + grace 300s → 15:20 采集停止  │
15:20 → ~15:5x 收盘清洗+compaction ┘  report.json 生成（T 目录 finalize）
T 日 16:00  cleaner 运行：T 目录已完整、无进程再写
T 日 21:00  夜盘开始 → 写 T+1 目录（与已删除的 T 目录无关）
```

- 周五：16:00 拉周五目录（周四夜盘+周五白盘）；周五晚夜盘归下周一目录。
- 远程 collector 若配置为跨段常驻（`service.sh`），16:00 时也不会再写 T 目录；
  删除 T 目录与其运行无冲突（lock/staging 为运行时文件，可随目录删除）。

### 4.3 故障与重入场景

| 场景 | 行为 |
|------|------|
| 拉取中网络中断 | rsync 重跑增量续传 / sftp 按 size 跳过已传文件；manifest 停在 pulled，重跑续推 |
| 校验失败（远程文件被改动/漏传） | manifest=failed；远程保留；报告列出差异文件；不 merge 不 delete |
| 合并中崩溃 | 权威库写回是原子替换，旧文件完好；重跑 merge 重入（幂等） |
| 删除失败（网络/权限） | manifest 停在 merged；远程保留；下轮重试 delete |
| K 线合成中崩溃 | 逐文件原子替换；重跑同桶覆盖；无重复 |
| 手工与定时重叠 | 进程锁直接拒绝后到者 |

## 5. 数据模型与存储

### 5.1 本地目录布局

```
ctp_data/                        # tick 权威库（迭代04 data_root，schema 不变）
├── 20260918/                    #   trading_day/<交易所>/<合约>.parquet + report.json
├── kline/                       # K 线根目录（kline_root，默认值，可配置）
│   ├── SHFE/
│   │   └── rb/
│   │       ├── rb2510_1min.parquet
│   │       ├── rb2510_5min.parquet
│   │       └── rb2510_15min.parquet
│   ├── DCE/
│   │   └── m/
│   │       ├── m2509_1min.parquet
│   │       └── m2509-C-3000_1min.parquet     # 期权与期货同品种目录
│   └── CFFEX/IO/IO2509-C-4000_1min.parquet   # 股指期权自成品类
└── cleaner/
    ├── manifest.json            # 拉取状态档案
    ├── cleaner.lock             # 进程互斥锁
    ├── staging/<host>/<day>/    # 拉取过渡区（merge 后默认删除）
    └── reports/clean-<day>.json # 每日清洗报告
```

### 5.2 K 线 Parquet schema

| 字段 | 类型 | 说明 |
|------|------|------|
| datetime | timestamp[ns] | 桶起始（交易所本地时间 naive，钟面对齐） |
| trading_day | string | 归属交易日 |
| exchange_id | string | 交易所 |
| instrument_id | string | 合约代码 |
| open / high / low / close | double | last_price 聚合（有效价） |
| volume | int64 | 桶内成交量（累计差分） |
| amount | double | 桶内成交额（累计差分） |
| open_interest | double | 桶末持仓量 |

- 唯一键：`datetime`（单文件内）；文件间按合约+周期唯一。
- 压缩：zstd（与 pyarrow 版本兼容即可）；行组默认。

### 5.3 配置文件 cleaner.yaml（示例，完整注释随代码提供）

```yaml
tick_root: ctp_data              # 本地权威库（相对仓库根，沿用迭代04 相对路径惯例）
kline_root: ctp_data/kline

pull:
  delete_remote_after_verify: true   # 需求3：校验通过且合并完成后才删除远程
  hosts:
    - name: server-linux-a
      backend: rsync                 # rsync | sftp | local
      host: user@10.0.0.1            # rsync/sftp 用
      remote_data_root: /data/tick
      # port: 22 / key 等连接参数按需扩展
    - name: server-win-b
      backend: sftp
      host: user@10.0.0.2
      remote_data_root: D:/ctp_data

kline:
```

## 7. 性能设计

| 关注点 | 设计 |
|--------|------|
| 合并吞吐 | 逐合约文件流式处理；读-去重-写单文件峰值内存 = 单合约行数 × 行宽（主力合约数十万行，Arrow 列式可承受） |
| K 线吞吐 | tick 全量扫描一次生成 1min，再由 1min 派生 5/15（总数据量降两个量级） |
| SFTP 小文件多 | 按目录分批 list；get 串行 + 可配并发（默认 4，Windows 侧避免压垮 sshd）；仅传缺失/尺寸不符文件 |
| rsync | 增量 + `--whole-file` 本质按块校验，无需额外处理 |
| 磁盘 | staging 在 merge 后即删；空间预检在前 |
| 指标 | 报告记录各阶段耗时（pull/verify/merge/delete/kline），首月实测校准 30 分钟目标 |

## 8. 可靠性与可观测性

- manifest 全程留痕 + 原子写；崩溃后重跑自动从最后状态推进。
- 清洗报告（`clean-<day>.json`）聚合：per-host per-day 状态、合并统计、

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 远程误删（正确性事故） | 高 | 三重保护（verified+merged 状态、manifest 留痕、路径白名单）；`--dry-run` 演练纳入验收 |
| Windows SFTP 大量小文件慢 | 中 | 按 size 跳过已传；分批并发（默认 4）；首日迁移用 `local` 后端走移动介质亦可 |
| 品种规则漏识别/误识别 | 中 | 真实合约清单 100% 识别率校准（3.5 节硬门槛）；unknown 告警不阻塞；规则表单测覆盖六所样例 |
| 本地磁盘不足 | 中 | 拉取前空间预检（×1.2）；staging 即用即删 |
| 远程与本地 schema 漂移 | 低 | 按字段名对齐合并、缺列填 null + 告警；权威库 schema 永不更改 |
| volume 差分跨日重置算错 | 中 | 3.4 节规则三条兜底 + 单测锁定（含夜盘跨零点、节后首日场景） |
| 16:00 远程清洗尚未完成（慢机） | 低 | 无 report.json 即跳过，次日补拉；数据不丢只延迟 |
| 本地未开机漏跑 | 低 | 补拉机制天然覆盖（远程数据未删除前始终可补） |

## 10. 待实现阶段明确的开放问题

1. **SFTP 实现选型**：`paramiko`（纯 Python，依赖引入）vs `subprocess` 调系统
   `sftp -b`（零依赖但批处理能力弱、错误语义糙）。倾向 paramiko；实施 Task 3
   开始前先核对 `bt_api_py` 既有依赖树是否已含 paramiko（避免重复引入）。
2. **多机器拉取是否并发**：默认顺序（staging 互不干扰、日志清晰）；
   若实测单机传输太慢再评估按 host 并发（配置项预留 `pull.concurrency: 1`）。
3. **K 线是否需要按 `trading_day` 边界强制开新桶**：夜盘 21:00 与白盘 09:00
   分属同一 trading_day 但钟面自然分桶，当前设计不需要额外处理；若后续
   研究 needing "按交易时段对齐的 15min 桶"（如 09:45/10:00 vs 钟面），
   在 aggregator 加 `align: clock|session` 选项，本期不做。
4. **删除后的远程 report.json 归档**：远程目录删除后，其 report.json 的统计
   已随 manifest（rows 记录）留痕；是否需要单独归档远程报告到本地
   `cleaner/reports/remote/<host>/`，实施时按磁盘代价决定（倾向归档，体积小）。
