## 1. 全局约束

1. **不改业务行为**：质量迭代只做"等价改写/补测/补注解/门禁"，任何行为变更需单独 issue。
2. **不用 `--unsafe-fixes`**：`ruff --fix` 仅用安全修复集。
3. **按仓分批**：每批单一主题、独立提交、可独立 revert；子仓改动不强制发版。
4. **测试全绿**：每批提交前，受影响的测试套件必须全绿（根 + 相关子仓）。
5. **例外显式**：新增任何 `ignore`/`noqa`/例外路径，必须同时登记到 `docs/tech-debt.md` 与本迭代文档。
6. **门禁先报告后阻塞**：新增的子仓门禁先以 report-only 运行，确认噪音可控后再切为阻塞。

  类型与结构治理按仓排期，可能跨迭代。
- **覆盖率提升有天花板**：`bt_api.py`(8864 行) 等巨型文件难以在单迭代内有效覆盖，
  55% 是阶段性目标而非终局。
- **棘轮依赖扫描口径稳定**：若后续调整 `ruff` 规则集或扫描范围，需重建基线（属预期，需在 PR 中说明）。
- **CTP 生成代码**始终在例外内，不纳入任何指标计算。
- **`docs/plans/` 74 份计划**只做状态登记，不逐份执行；执行与否由 owner 按价值决定。
