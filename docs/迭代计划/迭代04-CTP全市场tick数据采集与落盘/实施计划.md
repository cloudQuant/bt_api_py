**技术栈：** Python 3.9+（`from __future__ import annotations`）、pyarrow（Parquet）、pyyaml（配置）、pytest（离线 mock 测试）。

## 2. 全局约束

1. **Python 3.9 兼容**：不用 `slots=True`、不用 `match`、不用 `X | Y` 的运行时求值（一律配 `from __future__ import annotations`）。
2. **不修改已有代码**：唯一例外是 `MdClient.subscribe_batched()`（新增方法，已获授权，不改动现有 `subscribe` 行为）。
3. **测试离线**：不连真实 CTP；用 `SimpleNamespace` 注入原生 API mock（项目既有模式，见 `tests/test_instrument_queries.py`）。
4. **代码风格**：ruff，line-length 100，double quote，Google 风格 docstring。
5. **固定契约**（不可在实现中漂移）：
   - 落盘路径 `<root>/<trading_day>/<exchange_id>/<instrument_id>.parquet`
   - 去重键与排序键 `(action_day, update_time, update_millisec)`
   - CTP 无效价格哨兵（`DBL_MAX` / 非有限值）→ `None`（沿用 `instrument.py` 的 `_reference_number` 约定）
6. **TDD**：每个任务先写失败测试 → 实现 → 测试通过。
7. **不自动 commit**：需要提交时由用户显式指示。

### Task 4：Parquet 落盘与清洗（M1 最小闭环 → M3 完整）

**Files:**
- Create: `bt_api/bt_api_ctp/src/bt_api_ctp/collector/sink.py`
- Create: `bt_api/bt_api_ctp/tests/collector/test_sink.py`

**Interfaces:**
- Consumes：`TickRecord`
- Produces：

```python
TICK_ARROW_SCHEMA: pyarrow.Schema

@dataclass
class InstrumentReport:
    exchange_id: str
    instrument_id: str
    rows: int
    first_update: str | None
    last_update: str | None
    gaps: list[dict]

@dataclass
class SinkReport:
    trading_day: str
    instruments: list[InstrumentReport]
    dropped_ticks: int = 0
    generated_at: str = ""

class ParquetSink:
    def __init__(self, root: Path, *, merge_existing: bool = True, gap_threshold_sec: float = 60.0) -> None
    def write(self, ticks_by_instrument: dict[str, list[TickRecord]], *, dropped_ticks: int = 0) -> SinkReport
```

**实现要点：**
1. 按 `exchange_id` / `instrument_id` 分组，路径 `<root>/<trading_day>/<exchange_id>/<instrument_id>.parquet`。
2. 去重键 `(action_day, update_time, update_millisec)`，同键保留 `local_receive_time` 最大者。
3. 按 `(action_day, update_time, update_millisec)` 升序排序（夜盘 `action_day` 为前一日 → 自然排在最前，顺序正确）。
4. `merge_existing=True`：先读入已有 parquet，与新数据合并后再统一去重排序（中断恢复幂等）。
5. **原子写**：写 `<name>.parquet.tmp` → `os.replace`。
6. 五档 tuple 展开为 `bid_price_1..5` 等扁平列。
7. 生成 `<root>/<trading_day>/report.json`。
8. gap 检测：相邻 tick 时间差 > `gap_threshold_sec` 记入 `gaps`。

**测试用例（关键）：**
- 写入后文件存在且 `pyarrow.parquet.read_table` 可读，schema 与 `TICK_ARROW_SCHEMA` 一致。
- 重复 tick 被去重（rows 数减少）。
- 乱序输入 → 输出有序。
- 二次写入（merge）不产生重复（幂等）。
- `report.json` 内容：rows / first_update / last_update。
- 夜盘 + 白盘混合 → `trading_day` 目录正确、排序正确。

`has_night_session(calendar_day)` 的语义是**该自然日的晚上是否开夜盘**（调度用）：

- 夜盘在交易日的前一晚进行，故 **周五晚有夜盘**（与周一日盘同属一个交易日）；
- **周六、周日晚无夜盘**；
- **法定节假日前一交易日晚夜盘暂停**（与次一交易日之间夹有节假日）。

判定 = 当日是交易日，且当日至次一交易日之间**只隔周末**（无配置的节假日）。运行时以 CTP `GetTradingDay()` 为权威，日历仅作启动预判。

**测试用例：** 周末/节假日为 False、工作日为 True；`has_night_session` 对"周五晚有夜盘/周日晚无夜盘/周一晚有夜盘/节前最后交易日晚暂停/节后首日晚恢复"的判断正确；`next_trading_day` 跨周末与节假日正确；`from_file` 读取节假日文件。

### Task 9：CTP 行情订阅器（M2）

**Files:**
- Create: `bt_api/bt_api_ctp/src/bt_api_ctp/collector_ctp/subscriber.py`
- Create: `bt_api/bt_api_ctp/tests/collector_ctp/test_subscriber.py`

**Interfaces:**
- Consumes：`MdClient`（含 Task 7 的 `subscribe_batched`）、`CtpTickNormalizer`、`TickHandler`/`MarketDataSubscriber` 协议
- Produces：`class CtpMdSubscriber: def __init__(self, md_client, *, normalizer=None, batch_size=100, batch_interval_sec=0.1)`

**实现要点：**
1. `set_handler(handler)` 保存 handler。
2. `connect()`：设置 `md_client.on_tick = self._on_raw`（闭包捕获当前 handler），调用 `md_client.start(block=False)`。
3. `subscribe(instruments)`：调 `md_client.subscribe_batched(instruments, batch_size=..., interval_sec=...)`。
4. `_on_raw(raw)`：`normalizer.normalize(raw)` → 非 None 则 `handler.on_tick(tick)`；**异常不得穿透原生回调线程**（`try/except` + 错误计数）。
5. `run()`：阻塞直到 `stop_event`（用 `md_client.wait_ready` + 轮询休眠，避免忙等）。
6. `close()`：`md_client.stop()`。
7. 记录 `connection_generation` 变化时间，供 report 的断线窗口。

**测试用例（mock MdClient）：** `connect` 绑定回调并启动；`subscribe` 以配置批大小转发；`_on_raw` 喂入原始 dict → handler 收到 `TickRecord`；`normalize` 抛异常时回调不崩溃且计数 +1；`close` 调用 stop。

**验证：** `.venv312/bin/python -m pytest bt_api/bt_api_ctp/tests/collector_ctp/test_subscriber.py -q`

### Task 10：采集引擎（M3）

**Files:**
- Create: `bt_api/bt_api_ctp/src/bt_api_ctp/collector/engine.py`
- Create: `bt_api/bt_api_ctp/tests/collector/test_engine.py`

**Interfaces:**
- Consumes：`InstrumentProvider` / `MarketDataSubscriber` Protocol、`TickBuffer`、`ParquetSink`、`ShardConfig`
- Produces：

```python
@dataclass
class CollectionConfig:
    data_root: Path
    shard: ShardConfig = ShardConfig(strategy="by_exchange")
    asset_types: tuple[str, ...] = DEFAULT_ASSET_TYPES
    per_instrument_cap: int = 100_000
    flush_interval_sec: float = 5.0
    merge_existing: bool = True

class TickCollectionEngine:
    def __init__(self, *, provider, subscriber, config) -> None
    def run_once(self, *, duration_sec: float | None = None, stop_event=None) -> SinkReport
```

> **接口契约说明**：`normalizer` **不是** engine 的依赖——`MarketDataSubscriber` 协议承诺 `handler.on_tick()` 收到的是归一化后的 `TickRecord`，因此归一化由 subscriber 实现内部组合（见 Task 9，`CtpMdSubscriber(md_client, normalizer=...)`）。engine 只看到 `TickRecord`，这才是"主流程不感知交易所"的落点。

**实现要点：**
1. `run_once`：`fetch_instruments` → 按 `asset_types` 过滤 → `select_instruments(shard)` → `set_handler` → `connect` → `subscribe(ids)` → 主循环。
2. 主循环：每 `flush_interval_sec` 或 `buffer.should_flush()` → `drain()` → `sink.write()`；`duration_sec` 到期或 `stop_event` 置位则退出。
3. 退出前 flush 剩余缓冲 + 写 report。
4. 回调路径（`on_tick`）只做 `buffer.append(tick)`（+ 计数），不做 IO。
5. 空合约集 → 直接返回（不启动连接）。

**测试用例（全 mock provider/subscriber）：**
- 订阅列表 = 分片后合约；handler 收到的 tick 进入缓冲并最终落盘。
- `duration_sec` 到期后文件存在、report 生成。
- `stop_event` 置位后退出并 flush。
- 空合约集不调用 `connect`。
- 分片过滤生效（只订阅本机负责的交易所）。

**验证：** `.venv312/bin/python -m pytest bt_api/bt_api_ctp/tests/collector/test_engine.py -q`
