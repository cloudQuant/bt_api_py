## 1. 验收说明

本文档定义迭代04 交付物的验收标准，分**功能验收**、**性能验收**、**数据质量验收**、**可靠性验收**、**多机分片验收**、**扩展性验收**六个维度。每个验收项标注验证方式（自动化测试 / 手工验证 / 实测）与通过判据。

> 注：本迭代 M1–M5 已实现完成。凡可由离线契约测试证明的条目已通过，逐项证据见第 10 节；依赖真实行情环境的条目（性能基线、真实断线重连、多机部署）待交易时段用实盘账号实测。

## 2. 功能验收

### AC-1 合约全集查询

- [ ] 能通过 CTP 查询接口获取当日全部有效合约（含期货 + 期权）。
- [ ] 合约信息含：`instrument_id`、`exchange_id`、`asset_type`（future/option）。
- [ ] 期权合约含：`underlying_instrument`、`strike_price`、`option_type`。
- [ ] 查询结果能按交易所归类（SHFE/DCE/CZCE/CFFEX/INE/GFEX）。
- [ ] 默认仅保留 `future`/`option` 两类合约用于订阅，combination/tas 等其他类型被过滤（过滤规则可配置）。
- [ ] 查询失败时能重试，重试仍失败时给出明确错误退出码。
- **验证方式**：SimNow 环境手工/自动化跑通，检查合约清单输出。

### AC-2 行情订阅

- [ ] 支持分批订阅，单批数量可配。
- [ ] 订阅成功的合约能收到 tick；订阅失败的合约被记录并支持重试。
- [ ] 能处理断线重连并重新订阅。
- **验证方式**：SimNow 环境订阅若干合约，观察 tick 回调与订阅日志。

### AC-3 tick 采集完整性

- [ ] `OnRtnDepthMarketData` 回调的全量字段被记录，无裁剪（对照 `CThostFtdcDepthMarketDataField` 逐字段核对）。
- [ ] 每条 tick 记录含 `local_receive_time`（本地时间戳）与 `update_time + update_millisec`（行情时间，毫秒精度）。
- [ ] 每条 tick 记录同时含 `trading_day` 与 `action_day`（夜盘时段两者不同）。
- [ ] 每条 tick 记录含 `instrument_id` 与 `exchange_id`。
- **验证方式**：对照 CTP 回调结构逐字段比对归一化结果；单元测试覆盖 Normalizer。

### AC-4 内存缓冲

- [ ] 盘中 tick 先入缓冲，不逐条写盘。
- [ ] 缓冲有单合约与全局上限，超限有明确行为（告警或强制刷盘）。
- [ ] 定时（可配间隔）批量刷盘。
- **验证方式**：单元测试模拟高频 tick，验证缓冲上限与刷盘触发。

### AC-5 收盘清洗保存

- [ ] 收盘后自动触发清洗（白盘段与夜盘段各自触发，合并写入同一 trading_day 目录）。
- [ ] 数据按 `<root>/<trading_day YYYYMMDD>/<exchange>/<instrument_id>.parquet` 落盘。
- [ ] 夜盘 tick（21:00 起）归属次日 trading_day 目录（如周一 21:30 的 tick 落在周二目录）。
- [ ] 清洗含去重（按 `instrument_id + action_day + update_time + update_millisec`）、时间排序（含毫秒）、字段类型规整。
- [ ] 生成完整性报告 `report.json`（每合约 tick 数、起止时间、缺口区间，缺口含断线时间窗）。
- **验证方式**：模拟一个交易日（含夜盘段），检查目录结构与报告内容。

### AC-6 定时调度

- [ ] 支持 `--once` 手动触发。
- [ ] 支持交易日判断，非交易日不启动采集。
- [ ] 支持开盘前自动启动（cron / systemd timer / launchd 任一路径可部署），覆盖**两个启动时点**：夜盘段（交易日当晚 ~20:45）与白盘段（交易日当天 ~08:45），并支持提前启动后等待开盘（`--wait-open`）。
- [ ] **夜盘归属判断正确**：周五晚有夜盘（归属下周一交易日）、周日晚无夜盘、法定节假日前一交易日晚夜盘暂停（`--night` 模式下直接以退出码 3 跳过）。
- [ ] 支持 `--until-close` 跑到本交易组收盘（白盘 15:15 / 夜盘 02:30）后自动结束。
- **验证方式**：部署到测试环境，验证调度触发与交易日判断。

### AC-7 分片

- [ ] 支持按交易所分片（`strategy: by_exchange`）。
- [ ] 支持哈希取模分片（`strategy: hash_mod`）。
- [ ] 提供 `--validate-shards` 校验命令：输入各机分片配置，校验交集为空、并集覆盖过滤后的合约全集，输出"重叠/遗漏"诊断。
- **验证方式**：多机（或多进程模拟）配置不同分片，验证各自采集的合约集合互不重叠且并集完整；`--validate-shards` 对构造的重叠/遗漏用例能给出正确诊断。

### AC-8 接口抽象

- [ ] 定义 `InstrumentProvider` / `MarketDataSubscriber` / `TickNormalizer` / `TickRecord` 抽象。
- [ ] 主流程（engine/buffer/sink）不 import CTP 具体类型。
- [ ] 主流程只依赖抽象接口与 `TickRecord`。
- **验证方式**：用 mock 实现抽象接口跑通主流程（无 CTP 依赖），证明解耦。

## 4. 数据质量验收

- [ ] Parquet schema 固定且稳定（字段类型一致）。
- [ ] 同一合约同一 `(action_day, update_time, update_millisec)` 无重复记录。
- [ ] tick 按 `(update_time, update_millisec)` 单调排序。
- [ ] 落盘数据可用 pyarrow 正常读取，字段无缺失/错位。
- [ ] 抽样人工核对：与 CTP 行情客户端显示的盘口数据一致。
- **验证方式**：读取落盘 Parquet，脚本校验去重/排序/schema；抽样对比。

## 5. 可靠性验收

- [ ] 断线后能自动重连并恢复采集。
- [ ] 重连后重新订阅，不丢已订阅合约。
- [ ] 当日中断后重跑 `--once`：续采数据与当日已落盘数据合并去重，不产生重复（幂等）；不承诺往日数据补采（CTP 行情不可回放）。
- [ ] 断线时间窗被记录进当日完整性报告的缺口区间。
- [ ] 采集过程中单合约异常不影响其他合约。
- **验证方式**：人为断网/重启，验证恢复；当日重跑验证合并幂等。

## 6. 多机分片验收

- [ ] 各机器收盘后各自本地生成 parquet 与 report.json（本期不要求自动汇总）。
- **验证方式**：两机部署，核对分片合约集合与本地落盘结果。

## 11. 首轮真实验收结果（2026-09-16 下午盘，SimNow）

**环境**：macOS arm64 / Python 3.12 / SimNow 前置 `tcp://182.254.243.31:30011`（行情）、`:30001`（交易）/ 交易时段 14:0x–14:5x。

### 11.1 发现并修复的真实缺陷（离线测试未覆盖）

| # | 缺陷 | 现象 | 根因 | 修复 |
|---|------|------|------|------|
| 1 | CTP 深度行情**不填充 `ExchangeID`** | 落盘 `exchange_id=''`，文件平铺在 `20260916/` 下（无交易所层级），`finalize` 扫描为 0，report.json 为空 | 设计文档假设 tick 自带交易所；实测原生回调 `ExchangeID` 为空字符串，可靠来源只有合约查询结果 | `CtpMdSubscriber.set_instrument_exchanges()` + 回调内补全（原生值优先）；`engine.run_once` 订阅前注入合约→交易所映射；`ParquetSink.write` 对空 `exchange_id` fail-closed |
| 2 | `connect()` 未等待登录 | `subscribe()` 时尚未登录 → 只写入 `pending` → 登录后一次性全量订阅，**FR-2 分批订阅实际失效** | `MdClient.subscribe_batched` 在未登录时仅记录 pending；engine 立即 subscribe | `CtpMdSubscriber.connect()` 增加 `login_timeout_sec`（默认 15s）并调用 `md_client.wait_ready()`；对不支持 `wait_ready` 的宿主容错 |
| 3 | **中金所股指期权被漏采** | 默认 `DEFAULT_ASSET_TYPES=("future","option")` 会丢掉全部 692 个 IO/MO/HO 合约 | 实测 CFFEX 股指期权在 CTP 参考数据中 `ProductClass=6`（`spot_option`），不属 `option` | `DEFAULT_ASSET_TYPES` 增加 `spot_option`（需求为"全部期权"，必须包含） |
| 4 | **全市场单次合约查询无法完成** | 单次查询 120s 仍 `complete=False`（已收 15582 条未完），后续同类型查询被 CTP 流控拒绝（`query_submit_rejected`） | 全市场合约 1.7 万+，单次查询在 SimNow 上难以在合理超时内收完 | `CtpInstrumentProvider` 改为**按交易所逐一分批查询** + `query_timeout_sec` 可配（默认 60s）；任一交易所不完整即 fail-closed |

> 附注：CTP 原生回调对象在回调返回后即失效（事后访问会读到悬空内存，实测 `InstrumentID` 变成垃圾值 `'916'`）。本实现的归一化在回调内完成，符合该约束。

## 12. 第二轮迭代：缺陷修复与无人值守能力（2026-09-16）

针对第 11 节真实验收暴露的问题，本轮完成修复并补齐外部调度所需的全部能力。

### 12.1 修复的问题

| # | 问题（来自第 11 节） | 修复 |
|---|---------------------|------|
| ① | 运行期无任何进度输出，无法判断进程是否正常 | `engine` 增加**心跳日志**（`received/buffered/dropped/sub_ok/sub_failed/elapsed`，默认 60s 一次，可配 `heartbeat_interval_sec`）与刷盘日志、启动/结束日志；CLI 统一用 `logging` 输出到 stdout，供 journald/文件采集 |
| ② | 订阅结果不可观测（`OnRspSubMarketData` 是 `pass`） | `MdClient` 新增 `on_subscribe` 回调（`_MdSpi.OnRspSubMarketData` 转发）；`CtpMdSubscriber` 统计成功/失败/最后错误码，并展示在心跳中 |
| ③ | gap 检测 100% 合约报缺口，无区分度 | 新增**交易时段表**，缺口只在**同一连续时段内**判定：小节休息（10:15-10:30）、午休（11:30-13:30）、隔夜均不再计为缺口 |
| ④ | 并发启动触发查询流控，部分分片直接失败 | `CtpInstrumentProvider` 增加**指数退避重试**（`query_retries`/`retry_backoff_sec`，默认 3 次 × 2s 起） |
| ⑤ | 多进程重叠写同一文件无任何保护 | `ParquetSink` 写入加**跨进程文件锁**（`fcntl.flock`），且临时文件名加入 pid+uuid（修复了并发时 `FileNotFoundError` 的真实缺陷） |

### 12.2 修正的业务规则（重要）

原先按"前一自然日"判断夜盘是**错误**的。正确规则：

- **夜盘在交易日的前一晚进行**：**周五晚的夜盘 + 周一的日盘 = 一个完整交易日**；
- **周六、周日晚没有夜盘**；
- 法定节假日前一交易日晚夜盘暂停。

因此夜盘调度用 `Mon..Fri`（而非周日~周四）。数据落盘沿用 CTP `TradingDay`，
周五晚数据自然写入**下周一**目录，与该规则一致。
