## 2 权限类别口径（设计名，P0 固定具体 schema）

清单 §2 末段要求为每个实际动作标注 `observe`、`trade_write`、`session_control`、`account_admin`，不得沿用旧 READ/WRITE 标签来忽略登录、会话创建/删除或控制动作。本文件的归类口径：

| 类别 | 覆盖动作 |
|---|---|
| observe | 行情/账户/订单/成交/合约元数据等只读查询；本地阈值快照与本地监控对象记录（本地对象不等于远程 Monitor 接入） |
| trade_write | 下单、撤单、批量撤单，以及“控制写是否派发”的写路径准入动作（CTP `arm`/`pause`/`resume`、SDK `disarm_execution_gate`、案例级写门）。准入动作是否应拆独立子类待 P0 schema 裁决 |
| session_control | 连接/登录/登出、listenKey 创建/续期/删除、额外会话建立与关闭、`ReqUserLogout`、竞争登录、受控会话停止（`client.close()`） |
| account_admin | 账户模式/配置写（Binance `dualSidePosition`） |

所有 99 个案例在 runner 层都会先建立会话（Binance 为公共 server time 探测 `binance_client.py:180–189`；OKX 为公共 time + 签名 `account_config` `okx_client.py:190–203`；SimNow 为真实 CTP 登录 `ctp_client.py:237–271`），该统一的 runner 级会话建立不逐案重复标注，作为场所差异登记在 TH01/03/05 等行。
