## 2. 功能验收

### AC-1 远程数据拉取

- 两后端（rsync / sftp）+ local 测试后端均可：列出 trading_day 目录、
  拉取全量最终文件、排除 `*.lock` 与 staging 段文件。
- 远程"未完成"目录（无 `report.json`）被跳过且不删除。
- 已删除过的目录若远程重现，走全新流程（manifest 重新记录）。
- 拉取中断重跑：增量续传，不重传已完整文件。
- 补拉：staging 预置两天积压目录，一次 `run` 全部补齐。

### AC-2 校验与 manifest

- 正常流程：`discovered → pulled → verified → merged → deleted` 状态
  在 manifest 中逐步留痕（含时间戳与每文件 size/rows）。
- 故障注入（三选至少各一）：staging 缺文件 / 字节不符 / parquet 损坏
  → 状态 `failed`、报告列出差异文件、**该目录不合并不删除**。
- manifest 崩溃续推：阶段中途 kill 进程，重跑从最后状态继续。

### AC-3 去重合并写回

- 构造远程与本地重叠 tick（同键 `(instrument_id, action_day, update_time,
  update_millisec)`、不同 `local_receive_time`）：合并后唯一且保留最新。
- 合并后文件按 `(action_day, update_time, update_millisec)` 升序。
- 合并统计（added/deduped/total）与报告一致；权威库 schema 与迭代04
  逐字段一致（字段名/类型 diff 为空）。
- 写回为原子替换：合并期间读文件方始终看到完整旧版或完整新版。

### AC-4 远程安全删除（重点）

- **未拉取的目录不删除**（需求原文语义）。
- 校验失败（failed）的目录不删除。
- 合并成功（merged）且配置开启时才删除；删除后 manifest 记 `deleted`。
- `delete_remote_after_verify: false`：只拉取合并，远程原样保留。
- `--dry-run`：打印将删除的远程绝对路径清单，实际零删除（fake backend
  断言 delete 调用次数为 0）。
- 白名单：目录名非 `YYYYMMDD`、路径含 `..` 或不在 `remote_data_root` 下
  → 拒绝删除并告警。

### AC-5 K 线正确性（1/5/15 分钟）

- 手工构造的已知 tick 序列（含同秒多快照、夜盘跨零点、小节休息、
  无效价 0/inf、跨日 volume 重置）→ 1 分钟 OHLC/volume/amount/
  open_interest 与手算值逐项一致。
- 自洽性：`sum(1min.volume) == 5min.volume == 15min.volume`；
  周期内首开末收一致；`amount` 同法。
- 无 tick 的时段无桶（不为休息时段造空桶）。
- 真实数据抽验：选 3 个主力合约（不同交易所），用 20260918 真实 tick
  合成 1 分钟 K，与行情软件当日分钟线抽样对比（允许尾差，方向/量级一致，
  差异记录原因）。

### AC-6 K 线路径与品种归属

- 路径严格为 `kline_root/<交易所>/<品种>/<合约>_{1min,5min,15min}.parquet`，
  无日期层级。
- 六所样例品种归属正确（期货 `rb2510`→`SHFE/rb`、`SR509`→`CZCE/SR`、
  `IF2509`→`CFFEX/IF`；期权 `m2509-C-3000`→`DCE/m`、`SR509C5000`→`CZCE/SR`、
  `IO2509-C-4000`→`CFFEX/IO`、`si2512-C-12000`→`GFEX/si`、
  `sc2510P600`→`INE/sc`）。
- 真实清单校准：本地三个交易日全部合约文件名识别率 100%；
  无法识别的进报告告警清单且不阻塞其余合约。

### AC-7 跨日追加与历史回填

- 同一合约同周期文件：合成第 D+1 日后行数 = D 日 + 新增；同桶重跑覆盖不重复。
- `--backfill` 对本地 20260917 / 20260918 / 20260921 全量回填成功，
  输出文件按 `datetime` 全局升序。
- 回填后与"单日增量合成"再跑一次，结果逐行一致（幂等）。

### AC-8 调度与无人值守

- `run` 在非交易日（周末/节假日，用 `--check` 或日历注入）exit 3。
- 进程锁：重叠运行第二个实例被拒绝并告警。
- 磁盘预检：模拟空间不足时告警退出，不开始拉取。
- 本机 cron / launchd 装载示例并手动触发一次 `run --dry-run` 成功执行完整决策路径。
- 每日清洗报告 `clean-<day>.json` 生成且结构完整（per-host 状态、合并统计、
  K 线统计、异常清单、阶段耗时）。

### AC-9 幂等与故障重入（横切）

- 完整 `run` 连续执行两次：权威库行数不变、K 线行数不变、远程删除调用
  第二次为空操作、报告无新增异常。
- 各阶段中断重入（4.3 场景表）均有对应测试或演练记录。

### 9.5 实现期发现并修正的问题

1. **合并阶段会读入校验失败主机的 staging**：原按"日"合并，未区分主机，
   导致损坏文件被合并。已改为只合并该日校验通过的主机（`merge_day(hosts=...)`），
   失败主机 staging 保留以便诊断。
2. **`local` 主机路径与 `tick_root` 重叠会造成自删**：`reclaim` 删除
   `<remote_data_root>/<day>`，若配置误把权威库当远程源，一次正常运行的
   reclaim 会删掉刚合并的数据。已在配置加载阶段 fail-closed 拒绝重叠路径。
3. **期权/组合命名与设计初稿不符**：真实数据中 CZCE 期权为 `FG611C1000`
   （非预估的 4 位月份），组合合约为 `RM701MSC2100` / `c2701-MS-C-2000`。
   规则表最终以真实清单 100% 覆盖为准。
